### Added

- `export --chart` selects the rows a chart plots: `RESULT[:COLUMNS][@first=<n>|@where=<column>=<value>[,<value>]]`, a closed grammar that `--help` and `helpers.md` state. `@first=10` takes the saved table's first ten rows in its stable order, and `@where` the rows holding the listed values, in table order, so a top-ten chart no longer needs a recorded result of its own. Malformed text exits 2 with an `errors` row naming the part that does not fit; a column the table lacks, a value no row holds, or more rows than the table has is an error, and nothing is written. A `--dataset` takes no selection. The MCP `package` tool passes the syntax through unchanged.
- The manifest's `charts` entries record each chart's `columns`, row `selection`, `headers`, the value labels its rows use, its `percent` columns, and its `round` places, and `check-draft` reapplies them to the result's saved table: a chart file that differs, an unrecorded chart file, an entry whose file is missing, and an entry from an earlier export without that record each give a `charts` row, in both modes, so `release` refuses them; a draft exported before this change needs one more `export` before `check-draft` passes. The `numbers` check is unchanged.
- `foundation/display.toml` takes `[percent]` with `columns = [...]`, fractions shown 100 times larger, scaled exactly from the saved text before rounding, and `[results."<result>".columns]` and `[results."<result>".values.<column>]`, which name one result's columns and values over the global names, a value table replacing the global one for its column whole. Any other key is an error. The manifest's `charts` and `dataset_selection` entries record the percent columns and places.
- `export`'s `methodology_lines` state each file's shaping for `methodology.md`: the rows a chart selects, then each header's source column with `, times 100` for a percent column and the places it is rounded to.
- `export` reports `label_warnings`: each column whose one `[columns]` name labels files from results that answer different questions, with no per-result name. It warns and still writes the files.
- `check-draft`, without `--verify-only`, writes `START-HERE.md` into the draft before the inventory, which then lists it: plain text in three parts, what to send the audience (the deck once built, `methodology-note.md` when present, each dataset), what builds the deck (the attach list and the one-line prompt `assembly/m365.md` now gives), and what stays internal (`methodology.md`, `manifest.json`, `deck-rules.md`). `--verify-only` verifies it like any other file, and the report's `start_here` names it. `awb-package`'s report points the user to it.
- `check-draft` reports informational `draft_markers` rows for the word draft or the phrase working copy or not a numbered release in the deck's title, subtitle, slide headings and headlines, or title slide notes. `awb-release` runs `check-draft --verify-only` first, shows each row, and asks the user to confirm the wording or revise it before running `release`.
- `release` reports `open_caveats`, every caveat the release carries, new or carried forward: each bullet of the deck's Limitations and open caveats and Open questions slides, wherever they stand, then each represented flag released with its caveat. `awb-release`'s report lists each and never calls a release clean, or says nothing is outstanding, while one remains.
- `awb-status` reports each package's `latest_release_in_storage`, whether reachable release storage holds its latest release, and suggests recording where releases are kept when it does not.

### Changed

- An exported number column that `[round]` and `--round` do not cover is a gap when a cell the file holds has more than four decimal places in its saved text, trailing zeros dropped and any exponent applied, two fewer in a percent column: `export` lists an `errors` row naming an example cell and a `round_stub`, lines to paste under `[round]` once filled from the slide's number format, and writes nothing. A `[round]` entry must be a whole number from 0 to 20.
- `manifest.json`'s `dataset_selection` lists each dataset as an object with its `path`, `result_id`, `columns`, `percent`, and `round`, instead of its path alone.
- Release storage holds each release at `<location>/<investigation>/<package>/<n>/`, without the checkout's `released/` folder; `release`, `copy-releases`, their instructions, and `awb-status` use that path. The in-project `deliveries/<investigation>/<package>/released/<n>/` stays. Copies made earlier stay where they are, and `copy-releases` copies each release to the new path.
- When a revision comes with the request to mark a package delivered, `awb-package` shows the user the changed slides and waits for their yes before invoking `awb-release`, unless they said to release without seeing it.
- `deck-rules.md` tells the builder that a chart file's numbers arrive rounded and a percent column already holds percents, so it plots them as written.
