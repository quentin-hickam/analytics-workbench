### Added

- `reconcile()` in the validation helper records a filter's rows in, rows kept, and rows excluded by each rule as a `row_counts` step. Validation fails the step, naming the counts, unless rows in equal rows kept plus every excluded row, and the passing detail records the reconciliation, which backs "reconciles" wording in a finding. "Sums to" and "adds up to" wording is now its own kind, so neither that detail nor a judgment worded as a reconciliation backs it. The run script's producer example uses it.
- An investigation's shared SQL: result sessions load `investigations/<name>/views/*.sql` after the foundation views, in file-name order. Each file counts as producing code for every result of the investigation, so an edit stales them all, and so does a file added there later. Every result's evidence records the files as views, with the foundation views and publications they read, whatever its `views` setting. A file they read directly must be a publication or, read by its own path rather than a glob or folder, listed in every result's `code`, and `run.py` refuses, before it runs anything, a read outside that, such as a result whose `code` lacks the file.
- `[eda] where`, and `--where`, read `[parameters]` entries written as `$name`. A string becomes a quoted literal, a number a number, and a date or date-time a typed literal. A name `[parameters]` does not set, or a value no literal writes, stops the scan with a message naming it.
- The status collector lists, under `git.uncommitted_evidence`, results whose evidence names no producing commit while the repository now has one. `awb-status` reports them in one plain line and offers the rerun that records the commit.

### Changed

- Result sessions run DuckDB on one thread, so a rerun adds floating-point values in the same order and an unchanged result saves an identical table.
- A result's `views` entries must each be a `.sql` file directly under `foundation/views/` or the investigation's `views/`. `run.py` refuses any other entry, such as a view's logical name, before it runs anything; it used to record the entry as a missing file, and only `stale` noticed. The settings template documents the key.
- `validate()` raises a `ValueError` naming a joins spec's missing `keys` or `left_rows`, where it used to raise a `KeyError`. The settings template marks both as required.
- The analysis guide's "Add a result" says that a threshold, minimum or exclusion the brief does not settle is the user's decision, proposed before looking at which rows lead. It suggests `reconcile()` for every filtered population and a per-entity coverage count for every series summed over a period, with a shortfall recorded as a caveat. It says to keep full precision in result queries and round only for display, and that a result run before the first commit stays `uncommitted` until it is rerun after that commit. It names the `awb` MCP `run` tool first and the terminal command as the fallback, and shows how a producer imports a helper module from the investigation folder. `awb-explore` follows the same threshold rule and counts coverage for each entity in scope when a measure is summed.
- A validation check recorded as not assessed stays out of the audience narratives unless the user should act on it. When a review or the user corrects a claim a finding's text states, `awb-package` rewords that finding with `state finding --text` in the same revision, so a later revision does not start from the old claim.
