### Added

- `awb.py review-receipt start`, run right before the reviewer is launched, notes what the review will read, and `review-receipt record` keeps a draft review's report, the problems the user accepted with their reasons, and a copy of what the review read (the narratives, `foundation/review-rules.md`, the `revalidation_flags` fields that make a review stale, and each evidence file the manifest's `results` name, so a rerun makes the review stale) in the package's `review/` folder, beside `draft/`. `review-receipt show` writes nothing and reports that record as `none`, `current`, `stale`, or `failed`, with the inputs that changed and a diff from the reviewed copy, cut so its printed line fits one MCP read result. `record` refuses, leaving the record as it was, without a start or once what the review reads changed after it; `record --accept` amends the recorded report and is refused once what that review read has changed; and a report that does not pass is refused once it was read against an earlier draft, after a new `start` too. Over MCP, `show` goes through `read`, and `start` and `record` through `package`, which now takes `stdin`.

### Changed

- The package review converges. The first review of a draft is full and every later one is scoped against the receipt, and a scoped review that passes completes a request or a release. The user may accept a narrative problem with a reason, as they could a warning. A problem raised on a line unchanged since the prior review is marked and goes to the user, and after a second review in one request that still reports problems the agent stops and asks instead of reviewing again. In Claude Code the reviewer uses the awb MCP `read` tool when the session has it.
- `release` refuses, creating nothing, unless the review receipt is `current`, and records the review's kind, time, and accepted problems under `review` in the released manifest. `awb-release` reviews only when the receipt is not current, scoped against it, and shows the user the changed slides of any repair before releasing. `check-draft` reports the receipt's status in an informational `review` row.
