# Changelog

All notable changes to this project are recorded in this file. The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project uses [Semantic Versioning](https://semver.org/spec/v2.0.0.html). Each release is a Git tag `vX.Y.Z` with the zip archive attached to its GitHub release.

## [Unreleased]

### Changed

- A package can answer only some of the ledger's questions: the manifest's `questions` lists their IDs (absent or `none`, every root as before). Its **Open questions** slide then requires only those and the questions under them, the review checks them, from `review-rules check`'s `questions`, in place of the brief's **Business question**, and the review receipt reads the brief without that section, so a brief edit for other work no longer makes the package review stale.
- Simple questions take fewer tool calls and carry less fixed text. The project `AGENTS.md` no longer asks the agent to read both guides in every session, to settle terms with data before answering, to read the README for the active investigation or interpreter (the `awb` tools resolve both), to read history unless the ask turns on an earlier decision, to suggest a commit once a session, or to repeat that numbered releases are frozen (the release skills say so); `awb-explore` triggers only on "explore this dataset" or "profile this view", not on "look at this data".
- The `awb` MCP tool definitions, which hosts send with every request, are about a sixth shorter (7,691 characters, down from about 9,100); a test keeps them at or under 7,700.
- The status collector no longer repeats each finding's caveat under `active.caveats`; `awb-status` reports every `active.findings` `reason`. Its body drops rare-case detail about upstream probes, source-reference syntax, and timezones.
- The investigation `state.md` template drops its three explanatory paragraphs, which every `state` call printed; the promotion rule they held is in `workbench-guides/analysis.md`.
- `scripts/measure-instruction-load.py` also reports the current size of the MCP tool definitions, and the README's admin section adds a short note on cost per request.
- Python 3.12 is the default interpreter when installed; 3.10 or later still works. `awb-init` builds a new project's `.venv` with Python 3.12, else with the system's default Python 3 when it is 3.10 or later, and the README and `awb-init` say to run the MCP server registration with Python 3.12 (`python3.12`, or `py -3.12` on Windows) when it is installed. The registered interpreter is still the one that runs `install_helpers.py --mcp-config`.

## [0.4.0] - 2026-10-19

### Added

- `awb-init` ships `assets/awb_mcp.py`, a standard-library stdio MCP server that exposes the helpers as tools for hosts that confirm every terminal command. Each tool runs the existing command line (`src/awb.py <command>` or a skill script) as a subprocess. `read` is marked read-only and covers state, the question list, read-only SQL and profiles, stale, review-rules check, check-draft verification, status, saved EDA scan sections, and command help; the write tools are `records`, `data`, `run`, `package`, `release`, and `setup`. The project root comes from a `project` argument, then the single MCP root, then the working directory, and must hold `src/awb.py` except for `setup`. Write calls run one at a time. Results are bounded plain text, with long output saved to a file in a temporary directory private to the server process. The server speaks the legacy protocol through `2025-11-25` and answers every other request, `server/discover` included, with `-32601`.
- `awb.py sql --read-only` and `awb.py profile --read-only` run only SELECT statements, refusing COPY, ATTACH, INSTALL, LOAD, EXPORT, SET, a PRAGMA that sets, CALL, CREATE, and other statements, a SELECT whose plan calls a table function outside the read list (`enable_profiling` and `enable_logging` write files), and a SELECT calling `query`, `query_table`, `json_execute_serialized_sql`, or a macro that calls one (such as `histogram_values`), whose SQL is rebuilt from a string at every bind so the plan checked need not be the plan that runs, before any runs, and refuse `--out`. Their session installs no extension, keeps no persistent secret, spills to a private temporary directory, locks its configuration once the views load, and loads only CREATE and SELECT statements from view files, refusing a view file holding any other kind, ATTACH included, before any statement runs, and checking each statement's calls and plan the same way before it runs.
- `awb-scope` starts, sharpens, and rescopes investigations through an interview that follows the business question's dependent decisions, asking a decision alone when its answer shapes the next one and same-level decisions together, following up vague answers at once as concrete cases, and never putting a data question to the user. Scoping may finish with the question, population, purpose, or usefulness criteria held open as a ledger question that the brief names by ID. It replaces `awb-init`'s scoping interview and owns creating investigation records; `awb-init` now asks a new project's question in one line and hands it over. Install the eight `awb-*` folders.
- Each investigation keeps a question ledger: `questions.json`, rendered whole to `questions.md`, managed with `python3 src/awb.py questions` (`list`, `add`, `answer`, `status`, `edit`, `render`). Questions have never-reused IDs `Q-NNN`, a kind, who can answer them, and a status (open, answered, parked, declined, superseded). An answered question keeps its answer: a different one is refused, and a scope change supersedes the question and adds a replacement. A hand edit to `questions.md` is refused as drift, and `render` refuses to rebuild `questions.md` without `questions.json`.
- A result's settings table may declare `answers = ["Q-NNN"]`. Evidence recording refuses IDs the ledger lacks and questions a person answers, and `run.py` refuses both before it runs anything; `run.py` marks the questions answered and lists them in its output line, and `awb.py questions answer --result` links an already recorded result. Settings comparisons ignore `answers`, so declaring it makes no result stale.
- `awb-brainstorm` proposes new questions from the ledger, findings, and catalog, each naming what prompted it, who can answer it, and the decision it serves, and records the proposals the user keeps, parks, or declines.
- `check-draft` checks the deck outline against the slide rules (`outline`): a title slide with its subtitle, a headline of at most 15 words, at most five bullets, at most one chart, and a closing **Notes:** paragraph per slide, and no text outside a slide. Its `charts` rows also check each specification's form against the seven chart forms and its **Data:** line, which names the chart file's columns by role (`category: Region; value: Closed late (%)`), against the form's roles and the file's header. The packaging helper derives the slide structure from `findings.md` as it renders (`parse_outline`); the outline stays the only source and no structured copy is written.
- A reference deck renderer under `tests/` builds a `.pptx` with python-pptx from a parsed outline and its chart files, proving the deck contract complete without Microsoft 365. It is a test fixture, not shipped; its tests skip without python-pptx.
- `awb.py state` prints the ledger's open questions and the answered data questions awaiting recheck because any answering finding is flagged or superseded. `awb-status` reports ledger counts, open questions by answerer, and those awaiting recheck, and suggests `awb-scope`, `awb-explore`, or `awb-brainstorm` from them.
- Print-only `install_helpers.py --mcp-config copilot|claude|codex` entries for user-level MCP registration, with absolute interpreter and server paths, host-native JSON or TOML, and a separate merge destination. Unsupported hosts and mixed install/registration arguments are refused without writes.
- A user-level VS Code package reviewer with only file read/search and `awb/read` tools, plus a Copilot subagent launch branch that reports unavailable tools as a failed review.
- Parent and priority fields for ledger questions through the CLI and MCP tools, with missing-parent and cycle checks and priority-ordered tree rendering.
- Ledger-derived finding slide order, informational reporting of unlinked findings, and draft checks for slide order and the conditional Open questions slide.
- A headline approval checkpoint before full slides for new drafts or changed storylines.
- Add a conditional turn footer and plain conversation vocabulary to the workbench `AGENTS.md` template: name record changes and the next action, with IDs only alongside plain text.
- Check every skill's name, folder and metadata limits, with accepted and refused frontmatter forms; check repository files for the retired exploration skill name outside changelog history.
- Optional per-question `audience` wording for the Open questions slide, set through `questions add --audience` or edited in any status through `questions edit --audience`. Whitespace is collapsed, an empty value clears it, and question lists and the rendered ledger show it when set.
- Server registration warnings for Python older than 3.10 or an interpreter running in a virtual environment; the entry still prints unchanged.
- `read_xlsx` is on the read-only read list, so `sql --read-only`, `profile --read-only`, and the MCP `read` tool can read a landed Excel file, for example to check it before writing its conversion. It comes from DuckDB's `excel` extension. The read-only session still installs no extension, but loads one already installed when a statement needs it, with its configuration locked. Without the extension, `read_xlsx` or a plain `FROM 'book.xlsx'` fails on one line saying so and how to install it once without `--read-only`: `python3 src/awb.py sql "INSTALL excel; SELECT 1"`, or the `data` tool's `sql`. `read_xlsx` writes nothing: its arguments name a file, a sheet, a range, and how to read cells, and only `COPY`, which read-only SQL refuses, writes an `.xlsx`. The landing reference lists the file readers of read-only SQL and this install step, and the data guide sends an agent there when `sql --read-only` or the `read` tool refuses a function or needs an extension.
- A result that needs more than its query gets a producer module, `investigations/<name>/producers/<result-id>.py`, defining `produce(connection, sql, parameters)` and returning `(frame, measured)`. `run.py` loads it by result ID, registered by name as an import is, under a name no other result ID shares, so a dataclass or pickle in it works, and binds its `run()` in the module first, so adding a result never edits `run.py`; the `PRODUCERS` dict is gone. The file is named by the ID exactly, and `result_problems()` refuses an ID that is not a letter or digit followed by letters, digits, `.`, `_`, or `-`, so `run.py` exits 2 before it runs anything. `awb-init` repair moves an older `run.py`'s producers into modules.
- A result's settings table may list `code = [...]`, further producing files relative to the investigation, and `parameters = [...]`, `[parameters]` names of letters, digits, `_`, or `-` that its producer reads and no query names as `$name`. Each `code` path must be a file in the project, never a directory, since a file added to one later would go unrecorded; `run.py` checks this with the other settings problems and exits 2 before it runs anything, since a rerun replaces the prior evidence first.
- `awb.py state finding` warns, never refuses, with `--text` or a promotion to `supported`: on each number in the finding that its result's table, profile, checks, and settings do not record, read by the number reader `check-draft` uses, loaded from `src/packaging/draft.py` only then and skipped when that file is absent; and on wording that asserts a reconciliation or a completed check (sum, sums, summed, or summing to; add, adds, added, or adding up to; reconcile, reconciles, reconciled, reconciling, or reconciliation; checked or verified every, each, or all) when no passing check's name or detail uses wording of the same kind (reconciliation wording for a reconciliation, checked or verified wording for a completed check, so a scope judgment "Checked all date filters" never backs "sums to"), naming the remedy: state the check, with its tolerance, in a passing `values` or `metrics` judgment's detail and rerun, or reword. Unreadable evidence gives one warning that nothing was checked. The warnings print before the rows, so the MCP `records` tool returns them.
- An optional audience-facing `methodology-note.md` in the package draft: a short plain-language account of method, sources, definitions, exclusions, and limitations for the brief's Audience, written from the new `package-format/methodology-note-template.md`, which `install_helpers.py --package-formats` installs. When the draft holds it, `check-draft`'s names, numbers, claims, and Markdown checks and `review-rules check` read it, with rows naming the file, and the claims check holds the whole note to the strongest represented claim strength. The draft review checks that it states nothing `methodology.md` does not support. It travels beside the deck like datasets and is not attached to the builder; `methodology.md` stays the internal reference. Without the file, neither command reads or reports anything for it.
- A `## Appendix` deck section that holds `###` slides after the main sequence; a deck has one, and `check-draft` refuses a slide after it outside it. **How we know**, **Limitations and open caveats**, **Supporting datasets**, and individual findings may move there, and a required slide moved there still counts. The outline reader marks appendix slides and keeps their order, every check reads them, and an appendix finding slide is held to its claim strength. `deck-rules.md` tells the builder to open the appendix with a divider slide titled Appendix, which the reference renderer builds. `check-draft` reports `slides`, the main sequence's and the appendix's slide counts.
- An optional manifest field, `presentation_order`: the finding slide headings in the order the user approved. When it is a list, `check-draft`'s `storyline` rows hold every finding slide to it and refuse a list that misses or repeats a finding slide, names a heading no finding slide has, or is malformed; `export` keeps it, and `release` reads none of its headings as a provenance gap. The ledger-derived order stays the default proposal, and ledger priority and parent keep their analytical meaning, deciding Open questions membership.
- The investigation brief's Audience section records a deck length the user asks for and the headline checkpoint mode they prefer, and later packages reuse both. At the headline step, packaging reports the main and appendix slides against that length and proposes what moves to the appendix.
- A review rule may name a scope, `- Scope: line`, `slide`, or `document`, set with `review-rules add --scope`: what one violation covers. `review-rules check` groups a `slide` rule's matches into one entry per slide, read as the section a `#`, `##`, or `###` heading opens as the file renders (one slide in `findings.md`, one section in `methodology.md` and the note), with its heading, heading line, and every matched line; a `document` rule's into one entry per file. An entry lists at most 20 lines, with `more_lines` beyond, and the row carries `scope`. A rule without the field is checked line by line, as before, and `add` writes the field only when given. A Scope other than exactly `line`, `slide`, or `document`, a blank one included, is a reported problem with the rule `unchecked`, and `add` refuses until it is repaired, as for other fields. `--scope` passes through the MCP `records` tool.

- A chart specification's fields are list items at the depth of its first field, each one paragraph. An item nested under a field, a blank line before it or not, or a later paragraph inside one, after a nested item or not, is now a `charts` row naming its line that says to join it to the field or move it below the specification, and the fields after it still count instead of becoming slide bullets; a field-named item back at a shallower depth is a slide bullet.
- The reference renderer's bar, column, and line value axes span zero and every value and interval bound, so negative values are no longer cut off below a zero minimum: zero is pinned as the minimum when every value and bound is zero or more and as the maximum when every one is zero or less, an interval bound that reaches past every value is pinned as that side's limit, and the automatic scale holds the rest. A Line keeps zero unless its **Axis:** says non-zero baseline, and a bar or column keeps it whatever **Axis:** says. A negative value in a Stacked bar is refused. `deck-rules.md` states the rule for those forms only, leaving Scatter axes as they were, says a Stacked bar's parts are zero or more, and lists a part below zero as a chart that cannot be drawn as specified, which a builder asks about or reports.
- The `check-draft --help` epilog lists the `charts` rows for a file column no **Data:** role names and for text nested in a field.
- `check-draft`'s `questions` check reads `methodology.md` as it renders, as every other draft check but `numbers` does. A question only inside a comment or fenced code no longer passes; a question wrapped across lines, in a code span, or written with emphasis or a link still matches. The manifest's question matches as written or rendered the same way, so a code span showing it exactly counts even when it holds a markup character such as `[` or `~`. It must fall within one paragraph or heading, and the row now says so.
- `check-draft`'s `numbers` rows give the correct line after a comment holding a line break other than a newline (U+2028, a form feed, or NEL); the line used to be one lower than the real one.
- The `check-draft` help text, the comment above the helper's shared Markdown reading, `references/helpers.md`, and the design record now agree that every draft check but `numbers` reads both narratives as they render. `helpers.md` gains a `questions` row.
- Read-only SQL runs DuckDB's `histogram()` aggregate. The dynamic SQL check now reads each call's position from the parse tree. A function or table macro that builds SQL from a string (`query`, `query_table`, `json_execute_serialized_sql`, `histogram_values`, the `histogram` table macro) is refused where it is called as a table function, and a scalar macro calling one is refused wherever it is called. So `SELECT histogram(id) FROM orders` runs through `sql`, `profile`, and `read`, and `FROM histogram(orders, id)` is still refused. A view file's CREATE VIEW, CREATE TABLE ... AS, or CREATE MACRO is checked by the parse tree of its body, so a view using `histogram()` as an aggregate loads. Known limit: a CREATE whose body does not parse alone, such as a macro with two bodies or `CREATE TABLE ... WITH NO DATA`, is still checked by token, and `histogram()` is refused there in any position, with a refusal that says so. A comment glued to a token, as in `AS/**/TABLE` or `(/*)*/`, does not change where the body starts. Once a view file's CREATE MACRO runs, the session reads the macro's body back from DuckDB's catalog and refuses the view file if that body calls SQL built from a string, so a split of the CREATE's text that misreads the body still cannot leave such a macro in the session.
- `profile` counts map, list, and struct values, such as a `histogram()` result, by their full text, such as `[1, 2]` or `{0: 3}`, instead of failing on `unhashable type: 'dict'`. A long list is written out in full, so two lists that differ in the middle count as two.
- `provenance_gaps` reports only `{"unknown": reason}` objects and unread requirements lines; a settings value or column name such as `unknown_pickup` is no longer a gap. The manifest template says to record an unknown in that form.
- The number reader skips a DOI, such as `10.24432/C5CG6D`, after `doi:` or `DOI`, or bare when its suffix holds both a letter and a digit, so `check-draft` no longer reports its prefix as an untraced number; the suffix ends at whitespace or at a `,` or `;` before a digit, so a number glued after it is still read, and so is a bare `10.2500/litre` or `10.2500/1000`.
- `record_evidence()` records a producing file under an ignored directory by checksum, as it records other ignored files, so editing it stales the result; before, it was compared with the commit, which never holds it.
- `record_cleaning.py` refuses a row outside its table in `foundation/quality.md` or the catalog section it sets, such as one added after prose that follows the table, naming its line and ID ("rows at line 11 (Q-002) and line 12 (Q-003) sit outside the table under '## Active limitations and issues', whose rows end at line 7"), before writing anything. It used to skip such rows, report a decision naming one as "issues not in the scan", and could give a new row an ID they already held. A header without a `| --- |` separator under it is refused with its line, and a second table in such a section is refused as a second table, to go under its own heading. Every call reads the Correction record, so an issue row added at the end of the file, directly under that table, is refused by its line as not a correction row, with or without a correction in the call, rather than read as one; a row there with another table's columns is told to move to that table, not under the Correction record. A new row's ID skips any ID already in the first cell of a table row in the file.
- `scripts/build-dist.sh` refused to build the archive, because the README's MCP server section linked `docs/copilot-compat.md` outside a `dist:exclude` block. That sentence now sits in its own excluded block, and `tests/test_skill_surface.py` checks the README as the script reads it: the archive copy has balanced markers and no `docs/` link, and every link names a tracked file and resolves, anchors included, in the repository and in the archive copy.
- The README's **How it works** no longer says the builder receives the chosen datasets. As `START-HERE.md` and `assembly/m365.md` say, datasets and any methods note travel beside the deck and are not attached.
- `check-draft`'s `numbers` check skips only the comments and fenced code that the rendered reading drops. A `<!--` that opens no comment, in a code span or fenced code, escaped as `\<!--`, or the start of the empty comment `<!-->`, used to hide every number up to the next `-->` anywhere later in the file, while the draft showed them, so a draft with an untraced number there could be released. A comment starting at column 0 and never closed, which the `markdown` check refuses, now hides the rest of the file from `numbers` as from the other checks, as it would render. Fenced code is taken from the same reading; it differs from before only for a fence the `markdown` check refuses.
- The rendered reading every draft check shares finds a comment within a paragraph as CommonMark does, escapes first: a `<!--` in a link's or image's target or title, or in a code span after an escaped backslash or backtick (`` C:\\`<!--` ``), opens no comment; a target is read as CommonMark reads it, parentheses nested or escaped. Text such a `<!--` once hid up to a later `-->` reaches every check, and a `<!--` there alone is no longer refused as a comment never closed.
- `check-draft`'s `numbers` check reads text between escaped backticks, as in ``fell \` 37% \` in``, which it used to skip as a code span.
- `check-draft`'s `questions` check no longer accepts a question that `methodology.md` holds only in an image's text, which shows only when the image fails to load, or to a screen reader. The check reads an image as the picture it shows, so a question cannot run across one either. An image is found as CommonMark finds one: escapes, code spans, and autolinks, an email's too, are read first, so a bracket inside one does not end an image's text early, and a target may nest or escape parentheses or escape a quote in its title. The other checks still read an image's text.
- `references/helpers.md`, the `check-draft` help text, and the design record say which comments `numbers` skips and that the `questions` check leaves image text out; `helpers.md` also says that a fence or comment starting at column 0 and never closed hides the rest of the file rather than being read as text.
- `check-draft`'s `numbers` check pairs a code span's backticks across its whole paragraph, as the draft renders it. It used to pair them only within a line and the lines around it, so in hard-wrapped prose a code span closing on an earlier line paired its closing backtick with the next span's opening one, and a number between them, such as `37%` in a line after `` `status =`` wrapped to `` 'active'` ``, was skipped as code.
- A packaging commit recorded as unknown because the repository has no commit yet is no longer a `provenance_gaps` entry, nor is one in a project without Git, so release reports stop naming a missing commit nobody could have made. Any other unknown packaging state is still a gap.
- The `charts` check compares a chart file's headers NFKC-normalized, as it reads the **Data:** line, so a `CO₂` header matches a `CO₂` role, and `deck-rules.md` tells builders to find each column the same way.
- `awb.py sql --read-only` no longer answers every statement it cannot plan, an unbound parameter or an ambiguous column included, with advice to run it without `--read-only`; it returns DuckDB's error with the likely fix. Without `--read-only`, an unbound parameter gets the same fix, and `profile`, which binds no parameters, says to write the value into the query or run it with `sql --param`.
