# Agent feedback: CO2 analytics workbench usability session

The user’s task was completed: five factual questions answered, source and country classifications checked, eight slide outlines and six chart files prepared, a donor-readable two-page method note produced, and release 001 frozen and verified in the requested external storage. The user confirmed the release, rounding, EU-27 labels and final headline. This feedback draws on the per-turn friction log; environment restrictions and agent mistakes are distinguished from workbench defects below.

## 1. Ranked pain points and suggested fixes

1. **Major — `awb-package/SKILL.md`, “Review the headlines.”** A mandatory approval checkpoint interrupted a request that already provided the intended eight-slide storyline and authorized drafting. The first packaging turn delivered a headline checkpoint rather than full slide bodies. The user subsequently said they did not need internal rules, just what was needed from them. **Fix:** make the checkpoint conditional on unresolved substantive choices; treat a supplied storyline or explicit drafting authorization as approval to create a concrete full draft for review. Keep a headline checkpoint available for genuinely new storylines, without requiring another permission turn for routine drafting.

2. **Major — `package-format/methodology-template.md` and package delivery conventions.** The mandated methodology is an internal analytical reference, but the user asked for a donor methodology note. The initial thorough internal draft was unsuitable to hand to donors: result IDs, filenames, settings and repeated recorded questions. The distinction became clear only after the user corrected it. **Fix:** explicitly distinguish internal analytical reference from audience-facing methodology at package establishment, and provide a short audience-facing template by default when a user requests “slides plus a methodology note.” Use clear names such as `methodology-internal.md` and `methodology-donor.pdf` rather than relying on the user to infer that `methodology.md` stays internal.

3. **Major — `awb-status`, question ledger and findings counts.** The user asked five research questions but saw “17 questions” and “10 findings.” Counts included setup decisions, scope/cleaning decisions, the umbrella question, coverage checks and supporting result tables. Later chart projections and headline arithmetic added further entries. This caused a direct user question and required a bespoke tracking-summary file. **Fix:** distinguish user research questions, operational decisions, supporting checks and presentation extracts in records and status. Lead with “5 research questions answered” and show detailed ledger/result counts only on request. A saved chart projection should not automatically read as another research finding.

4. **Major — evidence/staleness handling in the runner and `awb.py state finding`.** Editing investigation methodology prose made r-009 stale as `uncommitted-code`, blocking a caveat update even though no analytical inputs, SQL or values changed. Earlier edits to the shared runner also marked all existing results stale. The safety mechanism is useful, but its dependency surface was broader than the actual computation. **Fix:** record and invalidate precise computational dependencies; distinguish analytical code/settings from narrative documentation. Support evidence-preserving metadata/caveat revisions without requiring an unchanged computation to be rerun. Surface which dependency caused staleness and why it belongs to that result.

5. **Major — `mcp__awb__setup`, `mcp__awb__records`, host approval configuration and `AGENTS.md` MCP-first instruction.** MCP reads worked, but writes returned `MCP tool call requires approval, but approval policy is never`. That made the preferred write path unavailable. Authorized local CLI writes worked, so this did not block the overall task. **Fix:** declare tool capability/approval availability at session startup; document a read-MCP/write-CLI fallback. Do not make agents repeatedly rediscover a host-level denial or imply users must repair connectors before work can continue.

6. **Major — `awb-init` prerequisites and commands using `python3`.** System Python was 3.9.6, while helpers require Python 3.10+. Initialization failed before setup could complete. A compatible interpreter and `uv` were available, but required manual discovery, virtual-environment creation and interpreter-specific commands. **Fix:** bootstrap should detect incompatible Python, locate a supported interpreter where possible, and offer one concise environment command. Persist the chosen interpreter so examples and tool wrappers use it consistently. Document that `uv venv` may create an environment without pip.

7. **Major — initial `foundation/quality.md` structure and `record_cleaning.py`.** The initialized file had useful prose but lacked the exact machine-required `## Active limitations and issues` heading. Cleaning recording failed until compatible tables/headings were added manually. **Fix:** ensure initialization emits a machine-compatible empty quality record and test the initialized structure against the recorder’s parser. Validate structural compatibility in installer `--check`, not at the first substantive cleaning write.

8. **Major — `awb-clean` scanner/recorder coverage.** The main user concern—real countries versus aggregates—and material per-entity coverage gaps were not generated scanner issues. The scanner found eight IQR-tail issues, while the recorder accepted only scan-issued IDs. The important semantic and coverage findings needed separately appended quality rows. **Fix:** support analyst-authored semantic/coverage issues through the same record helper, with evidence references, without fabricating scanner output or splitting records across helper-managed and manually maintained structures. Add optional entity-grain coverage checks, while keeping geopolitical inclusion decisions explicit.

9. **Minor — `package-format/findings-template.md`, `deck-rules.md` and user-specific package structure.** Generic templates call for Answer/How-we-know/Limitations slides and main-body caveat bullets. The user explicitly requested exactly eight slides and caveats in footnotes or a note. **Fix:** make these defaults configurable package choices and document their precedence once. A compact donor deck should not require repeated explanations of why it overrides generic extra slides.

10. **Minor — `foundation/display.toml` defaults and chart exports.** The initial exports retained floating-point artifacts such as `0.42541799999999996`, and the source label `European Union (27)` differed from the slide label EU-27. Both required a user correction before manual assembly. **Fix:** establish display precision and audience label mappings when creating chart specifications, not only after export feedback. Provide a preview of the actual CSV, require chart-file precision to match the intended displayed precision, and preserve unrounded analytical results separately. Existing `[round]` and `[values.country]` machinery solved this very well once configured.

11. **Minor — `check-draft` claim-language checks.** The checker treated a negated statement about not establishing “the effect of a policy” as unsupported causal wording. **Fix:** recognize explicit negation and caution language where practical, or report it as a review candidate rather than an automatic error. Independent review can distinguish a causal assertion from a caveat denying causality.

12. **Minor — `check-draft` numbers and non-result metadata.** Historical boundary years, source row/location counts, GDP currency base year, source-edition years and the “365” product name required allowlisting despite being documented metadata rather than novel analytical claims. **Fix:** support typed source/reference metadata in provenance and improve date/version/product-name handling. Keep strict evidence requirements for genuinely derived quantities; never solve that by allowlisting unrecorded calculations.

13. **Minor — README/assembly convention centred on Microsoft 365 Copilot.** The user wondered whether the delivery depended on a Copilot licence. The package itself consisted of ordinary outline/CSV files and was suitable for human assembly. **Fix:** lead with builder-neutral package instructions and ship a manual assembly guide alongside the optional agent-specific guide by default. Explain “ready to assemble” versus “a built PowerPoint deck” clearly.

14. **Minor — Git requirements under this filesystem policy.** `.git` writes were prohibited, so commit provenance and repeated “suggest committing” instructions were impossible to satisfy. Hash-based evidence kept the task moving. **Fix:** expose a supported no-Git mode early, preserve input/producer hashes, and report the limitation once rather than suggesting impossible commits repeatedly. This was an environment limitation, not an analytical failure.

## 2. Contradictory, ambiguous, lengthy or missing instructions

- **Approval cadence:** the package skill requires an explicit headline wait, while the general collaboration instructions say to finish authorized, reversible drafting and avoid repeated permission requests. In practice the checkpoint was treated as mandatory, but it cost a turn even after a concrete user outline. The intended exception should be explicit.
- **Template versus requested deliverable:** exact-eight-slide structure and footnote caveats conflicted with generic extra-slide/body-bullet requirements. User instructions correctly won; this needed recording and an explicit reviewer brief.
- **Meaning of “methodology note”:** missing audience distinction was the largest deliverable mismatch. Internal complete methodology is valuable, but is not automatically the note a donor should receive.
- **“Prefer MCP whenever offered”:** does not specify what to do when read calls work and every write is rejected by host approval policy. The CLI fallback was inferred.
- **Quality-record extension:** the clean skill/recorder does not provide a clear supported write path for real issues that the scanner did not emit.
- **Source candidate at init:** source-register fields assume an assessment basis. Initialization only had a user-nominated URL; “not yet assessed” was used rather than inventing fitness evidence or fetching beyond initialization scope.
- **Population policy:** the workflows did not supply country-versus-aggregate semantics automatically, which is appropriate, but no simple metadata-audit workflow was provided. ISO presence would have silently lost Kosovo and admitted Antarctica as a ranking country. The source inventory and retained documentation settled this.
- **Record vocabulary:** helpers call every result a finding, including chart projections. Status and report instructions should not make internal terminology the user’s mental model.
- **Instruction length:** package skill, contract, review, helper reference, slide template, methodology template, manifest template and deck rules duplicate many obligations. Reading and reconciling these was disproportionate to a bounded narrative revision. A short role-based checklist with detailed references only for exceptions would help.
- **Report requirements:** exhaustive IDs, provenance flags, chart-to-result mappings and internal rule links are useful in files but excessive in ordinary user updates. This user explicitly preferred practical next steps and a one-line final file-routing answer.

## 4. Deviations and judgment calls

- Used local CLI for writes after the preferred MCP write tools were demonstrably unavailable. Did not repeatedly prompt the user to fix connectors, retry denied writes, or work around `.git` restrictions.
- Honoured the user’s exact eight-slide structure and footnote preference over generic slide-count/content defaults. Recorded the override and gave it to the independent reviewer.
- Added a separate donor methodology Markdown/PDF while retaining the mandatory internal reference. This satisfied the user’s deliverable rather than exposing internal records to donors.
- Recorded semantic classification/coverage issues manually in quality prose where the cleaning helper could not accept non-scanner issues; did not invent scanner IDs or manually mutate helper JSON.
- Used an explicit source-wide entity map, retaining every original record. Kosovo remained eligible despite null ISO; Antarctica was excluded only from rankings; historical entities/events and regional/income aggregates were not extra current countries. Unknown future labels remain unclassified rather than silently passing.
- Changed the failed cumulative completeness assumption to a transparent recorded-observation metric, with early gaps disclosed and subsequently accepted by the user. Missing years were never imputed as zero and predecessor-state totals were not added on top of successor series.
- Declined to invent precise USSR/Germany allocation weights absent from the reviewed current OWID documentation. Distinguished documented predecessor metadata from an unverified allocation formula.
- Added presentation projections and scalar headline checks through the normal runner because the packaging/evidence contract requires every reported computed number to be recorded. No substantive accepted answer was changed, but this contributed to bookkeeping growth.
- Narrowed the user’s initial wealthy-country summary to named compared countries; user accepted the factual caution. Later compacted their suggested final headline to the template’s length limit while retaining both growth and consumption; the user explicitly approved the tighter wording after release.
- Used read-only reviewer subagents only where the package/release skill explicitly required them; otherwise did the work directly.
- Suppressed some exhaustive internal reporting in chat in favour of user-relevant files and outcomes. The user specifically did not want skill-rule detail; complete records stayed in project files.

## 5. Disproportionate time and token costs

- Reading/reconciling overlapping package instructions and exact structural/numeric checks was heavy relative to simple donor edits.
- The mandatory headline checkpoint prolonged packaging even after an explicit user storyline. It also produced a large internal draft before the useful donor-facing note existed.
- Historical entity documentation required substantial primary-source searching and retained-code reading. This was justified by the question, but broad searches wasted attention; going directly to OWID pipeline/regions documentation was more effective.
- Bookkeeping counts, chart-only results and required claim promotions created more user-visible “questions/findings” than the five requested research questions. Explaining those counts was avoidable overhead.
- Broad stale dependencies caused unchanged results to be rerun; later using new SQL/settings result tables with the default producer avoided this.
- Environment setup consumed time locating Python and adapting MCP/CLI usage before any data work.
- Chart decimal formatting and EU naming should have been handled on the first export, avoiding a release-preparation revision. Independent review usefully caught the remaining label shorthand.
- Full source-wide entity mapping and semantic coverage auditing were substantial but directly justified by the user’s cleaning concern and prevented real analytical errors.

## 6. What worked well

- **Shared foundation and explicit country semantics:** one canonical entity classifier protected all five analyses and correctly preserved Kosovo while avoiding aggregate double counts. No original data was deleted.
- **Pinned acquisition and external retention:** the complete original CSV, codebook and references were fixed to a GitHub revision, hashed and verified in external landed storage. Acquisition retention was idempotent.
- **Validation before promotion:** the cumulative coverage failure exposed a genuine material issue before an unsupported result became a finding. Join-grain and null checks caught implementation/coverage problems early.
- **Analytical separation:** accepted results stayed descriptive, not causal; endpoint differences were not sold as trends or program effectiveness. GDP gaps, Libya and small-base relative reductions remained explicit.
- **Saved SQL/default producer:** additional sensitivity and headline checks could reuse the accepted population, parameters and queries without modifying the shared runner or disturbing earlier evidence.
- **Metric sensitivity:** the coal check found only five shared countries in the two top tens and a meaningful Algeria small-base example. This gave the user a concrete presentation choice rather than hiding sensitivity.
- **Display machinery:** shared rounding and value mappings produced clean, fixed-precision CSVs and persistent EU-27 naming without altering analytical results.
- **Independent review:** the read-only review caught two missed EU shorthand labels; after repair all six rules passed. It added value beyond mechanical checks.
- **Builder-neutral artifacts:** the outline, chart CSVs and manual instructions were usable without Copilot. The donor PDF was rendered, visually inspected and confirmed to be two pages.
- **Freeze/copy verification:** `awb.py release` returned released true for 001, no local verification differences, no missing external acquisitions, and a verified storage copy. The user independently confirmed those outputs.
- **Final user outcome:** the donor note was accepted as exactly right, the cautious consumption wording was accepted, and the user could build the deck themselves from the delivered files without further clarification or permissions.
