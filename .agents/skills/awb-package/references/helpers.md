# Diagnosing a helper's rows

`awb-init`'s `scripts/install_helpers.py` installs `src/packaging/draft.py` and restores it when missing. Call the project's copy, customized or not; open its source only to adapt or debug it.

- Every draft check but `numbers` reads `findings.md` and `methodology.md` through one reading in the helper (`_view`), so a form that hides text from a reader hides it from every such check, and text a reader sees reaches every such check; `numbers` reads source lines as its row below says. The reading covers this Markdown subset:
  - ATX `#` headings starting their line, indented at most three spaces. A heading's text is compared as it shows, with whitespace collapsed and code spans and autolinks unwrapped, so `` ### Revenue by `region` `` and `### Revenue by region` are one heading.
  - Paragraphs, block quotes, and bullet or numbered lists, nested or not, read in place. Tables read as text.
  - Fenced code starting at column 0, which is code.
  - Comments starting at column 0, ending on the line holding `-->`; text after `-->` on that line is read. A comment within a paragraph must close within that paragraph.
  - A **Claim strength:** line counts only opening a top-level paragraph at column 0; text on the lines below it may continue that paragraph.
  - A chart specification is a paragraph or list item that renders opening with `Chart N.`, as `**Chart N.**` does. Its fields are the list items directly under it that open with a field name (`Data:`, `Highlight:`, `Axis:`, `Interval:`, `Source:`, `Caveat:`, `Alt text:`) not yet given; a blank line after a field, or any other block, ends them, so a **Caveat:** bullet after a blank line is the slide's.
  - The deck outline (`parse_outline(text)`, `read_outline(path)`) is derived from this reading and never written: the `#` heading and its first paragraph make the title slide; each `##` section but **Findings** is a slide, and each `###` a finding slide; a slide's top-level list items are its bullets, deeper items nested under them; a paragraph opening **Headline:** or **Notes:** is its headline or notes. A paragraph in a block quote is a paragraph of its own, unless the quote sits in a list item, where it continues that item. A later paragraph in a list item continues that item only when no deeper item comes between them; after a deeper item it is a paragraph of its own, so it is reported rather than joined to the deeper item or a chart field.
  - Inline markup is read as the text it renders. Emphasis and strikethrough markers and zero-width characters render as nothing, `<br>` as a space, and escapes and character references as the character they stand for, so `**leads** to` reads as leads to and `orders\_view` as orders_view. A link's or image's text joins the words around it and its target is dropped, though a methodology section's link targets still count as citations. A reference link `[text][label]` never resolves, since definitions are refused, so it shows as written and its label is read as text: `[carrier comparison][r-009]` cites r-009, and `[the view][orders_view]` is a `name` row. The claims check also reads it with the label dropped, as it would render resolved. A backslash hard break is a space, and a backslash before a backtick, `<`, or `&` makes it a literal character. CommonMark shows an unmatched marker as a character, so the claims check reads each marker both as nothing and as a word break: `x*drives` reads as drives. Code spans are code: the names scan reports them, at their opening line when one crosses a line break, and the claims check skips them.
  - Known limit: a square bracket outside a link renders as itself but is read as nothing, so a word glued to one joins the word inside it (`results[r-009]` reads as resultsr-009 and cites nothing). Leave a space before a bracket. For the same reason, and because an unmatched `*` reads as nothing even when escaped, a **Data:** line cannot name a chart column whose header holds `[`, `]`, or `*`; give the column a header without them.
- `markdown` rows (`markdown_problems(draft)`): `file`, `line`, and `problem`, worded `unsupported Markdown: <what> at line N; rewrite as <how>`. One row is given for each form outside the subset that could hide text or move it between slides:
  - a heading, code fence, comment, or **Claim strength:** line inside a list item or block quote;
  - a fence or comment indented from the start of its line;
  - a **Claim strength:** line that is indented, inside a paragraph, or after a comment;
  - text underlined with `=` or `-` (a setext heading);
  - text indented four or more spaces, which renders as code;
  - an HTML block, or an inline HTML tag other than `<br>`, whose attributes can hide the text it wraps;
  - a link reference or footnote definition, which renders nothing where it stands;
  - a fence or comment never closed.
  A refused form is read as text, and its row fails the check, so nothing is guessed at.
- `findings` rows (`check_findings(path, *, names=(), roots=())`): `line`, `kind` (`code`, `path`, `file`, `identifier`, `sha`, or `name`), and `text`. Comments and Markdown link targets are skipped.
- A `name` row's `text` is a name from these sources: the investigation and package names; the view and table names created or read in `foundation/views/*.sql` and in the views the investigation's evidence cites, without CTE names or table functions; the settings keys of `settings.toml` and of the settings files and resolved settings that the investigation's evidence records, as top-level keys and the dotted path of every nested key (a nested key's bare name is usually a plain word, so it is left out); and the result IDs of `investigations/<investigation>/evidence/*.json` and the evidence links in its brief, state, and history. A name of letters only is never in the set, since it collides with ordinary words. `check-draft` passes those plain-word names as `roots` instead: a slash token with any recorded name as a segment, such as `orders/region`, is a `path` row, while a slash between two other plain words, such as yes/no, is prose.
- `outline` rows (`outline_problems(findings_path)`): `slide` (a slide's heading, `title`, or where stray text sits), `line`, and `problem`, one per break of the slide rules: no `#` title or subtitle line; anything else on the title slide; text before the title, under a second `#` heading, or under **Findings** before its first finding; a `###` finding outside `## Findings`; a **Headline:** line on a finding slide, or none or several on another; an empty headline or one over 15 words (counting whitespace-separated words that hold a letter or digit); more than five bullets except on **Open questions**; more than one chart; a paragraph that is no headline, chart, or notes; and no **Notes:** paragraph, several, or text after it. The title slide needs no notes, and holds at most one **Notes:** paragraph.
- `storyline` rows report the finding slides to move: those outside the longest run of slides already in ledger order, each with `position`, `expected_position`, and the `question` that ranks it, so one moved slide is one row. Matching methodology sections supply represented result IDs and evidence links; those results' recorded settings `answers` supply question IDs. The [contract's Ledger storyline](package-contract.md#ledger-storyline) gives the ordering rule. `unlinked_findings` names slides answering no ledger question; it is informational and those slides go last. Missing evidence supplies no declared linkage and is reported here; existing evidence must name readable TOML with that result's settings table, whose answers must be a list of existing data question IDs. Malformed declarations fail, including when the ledger is empty.
- `open_questions` rows report a missing or unnecessary **Open questions** slide, a slide in the wrong position, or required question bullets missing, repeated, or replaced by other text. The input is the outline reader's rendered top-level bullet text, compared exactly to rendered ledger question text; inline formatting uses the subset above. Nested bullets and charts are refused on this slide. Paraphrases, question IDs, and owner commentary are not alternate matching forms. This check does not judge whether ledger wording suits the audience; the draft review does. The [contract](package-contract.md#ledger-storyline) defines which questions belong and why this slide has no five-bullet cap.
- `charts` rows (`check_charts(findings_path, charts_dir)`): `chart` and `problem`, one per specification numbered out of order, specification without a file, file without a specification (worded to leave a blank line before it when the specification continues the paragraph or bullet above it, which renders it inside that block), non-chart file in `charts/`, or file without data rows; then, per specification, a form outside the seven in `deck-rules.md`, no **Data:** line, an entry that is not `role: column header`, a role its form does not take, a role named twice that the form takes once, a role the form needs and the line lacks, a series with more than one value, a named column the file's header lacks, and a column of the file's header that the line names by no role (`chart_data(chart)` reads the line).
- `headings` rows (`heading_problems(draft)`): `heading` and `problem` for a `###` finding heading that methodology has no section for, or that findings or methodology repeats.
- `questions` rows (`question_problems(draft, record)`): `result_id` and `problem`, with `question` when the manifest records one, for a `results` entry without a question, or whose question `methodology.md` does not repeat verbatim as it renders. Each paragraph or heading is read as it shows, code spans unwrapped and whitespace collapsed, and the question matches as written or rendered the same way, so a question wrapped across lines or written with emphasis or a link still matches. It must fall within one paragraph or heading. A code span counts, since it shows its text: a question shown exactly in one matches even when it holds a markup character such as `[`, `~`, `*`, `_`, or `\`. A question only in a comment or in fenced code does not count.
- `claims` rows (`claim_problems(draft, represented, claims)`): a causal phrase above its slide's claim strength as `line`, `section`, `phrase`, `claim`, `results`, and `problem`; a represented result without a recognized Claim cell as `result` and `problem`; a finding without a methodology section, or whose section's **Claim strength:** lines are missing, repeated, unrecognized, at another strength, or, for a causal claim, naming a design other than the one `state.md` records for its cited results, as `section` and `problem`. Sections sharing a heading pool their citations and declarations. The phrase list is `_CAUSAL` in the helper; whole words only, so data-driven is prose.
- `numbers` rows (`check_numbers(path, values, *, allowed=(), claim_lines=())`; `check-draft` passes the line numbers of the **Claim strength:** lines the `claims` check accepts as `claim_lines`): `file`, `line`, and `text`, the number as written with its unit or the letters written against it, such as `21.3%`, `4.2M`, `1.5e6`, or `5GB`; a currency sign is left out, and so is a USD, EUR, GBP, JPY, CHF, CAD, AUD, CNY, or INR code written against the number, as in `USD4.2M`. The values are each represented result's `results/<id>.csv` cells, the numbers in its `results/<id>.profile.json`, and its evidence's check details and settings, as magnitudes, so a sign carried by words such as "fell" still traces. JSON numbers are read exactly as written, never through a binary float. A cell that is a number whole is that number; any other cell, check detail, or settings text is read the way a narrative line is, adding each number it states and, with a scale, the scaled value too, so `$4.2M` records 4,200,000 and an ID such as `ORD-123` records nothing.
  - **Tracing.** A number written to d decimal places traces to a value within half a unit of its last place (`1.5e6` to within 50,000), compared exactly at every written digit; a percent or percentage points also to a fraction 100 times smaller (`21%` to 0.214); a scale such as `k`, `M`, `bn`, or `million` also to the scaled value; and the lower bound of a range such as `10-15%` or `10 to 15%` takes the upper bound's unit. `%` and the word units (`percent`, `per cent`, `percentage points`, `pp`, `thousand`, `million`, `billion`, `trillion`, `mn`, `bn`, `tn`) belong to their number across any whitespace, a line wrap included; a letter scale (`k`, `M`, `b`) or `x` only when written against it, so `5 m` is 5. Scientific notation is read with any mantissa, such as `1e-5`, `12.5e3`, `.5e-3`, or `5.e-3`; an exponent too large to hold never traces. Digits joined by dots, commas, slashes, or colons, or three-digit groups joined by spaces, are one number: thousands grouping such as `1,240` and a single decimal point trace; a version or address, three or more dotted parts not all three-digit groups such as `3.12.1` or `10.0.0.1`, is skipped; and any other join, such as `1,2,3`, the decimal comma `21,3%`, `3/4`, `14:05`, `1.234.567`, or `1 000 000`, is reported and never traces, so write it as `1, 2, 3`, `21.3%`, `75%`, or `1,234,567`.
  - **Reading fails safe.** A number is skipped only in one of the contexts below, each of which marks it as no quantity or, on a **Claim strength:** line, as copied from the record. Every other number is read, including one whose context leaves it in doubt, and is reported unless it traces or is allowed; clear such a row by rewording, such as ending a date or year with a comma, or with an `allowed_numbers` entry and its reason. A line that wraps a paragraph, in a quote too, is read with the lines around it, so a context or a unit split from its number by the wrap is still seen. Where a context below says the period ends, it ends at punctuation, at a dash before a space, or at the end of its paragraph: a word after it could make its last number a count, as in `in 2000 orders`.
  - **Skipped.** Code, HTML comments, and link targets. Paths whole: a slash token, starting with a letter, `_`, `~`, `./`, or `../`, that starts with `./`, `../`, or `~`, has two or more slashes, starts with a project folder (`data`, `foundation`, `investigations`, `deliveries`, `src`, `views`, `queries`, `results`, `evidence`, `exploration`, `scans`), or ends in a file name with a known extension, such as `results/r-001-77.csv`. A file name with a known extension (`.md`, `.py`, `.csv`, `.tsv`, `.parquet`, `.json`, `.jsonl`, `.sql`, `.png`, `.svg`, `.jpg`, `.jpeg`, `.pdf`, `.htm`, `.html`, `.duckdb`, `.db`, `.xls`, `.xlsx`, `.docx`, `.pptx`, `.yaml`, `.yml`, `.toml`, `.txt`, `.log`, `.ipynb`). A hyphenated identifier whose first part is one letter, holds a digit or `_`, or has a capital after its first letter, such as `ORD-123-45`, `COVID-19`, `Q-3`, or `r-001`, and the chart file stem `chart-1`. A number glued to a letter before it or to a name's `_` (`Q2`, `FY2026`, `H1`, `late_77`), or to letters and digits after it (a hash such as `3f9a2c1`); a version or address, as above; a zero-padded code such as release `002`. Numeric dates (`2026-06-30`, with or without a time, and `6/30/2026`), and times with am, pm, UTC, or GMT or with seconds (`9:30am`, `14:05:30`). A day from 1 to 31 before or after a month name, with or without a year, where the date ends or runs to another date (`June 5, 2026,`, `5 June.`, `June 1, 2026 to June 30, 2026`). A year from 1900 to 2099 after in, from, since, during, until, till, through, before, after, between, year, FY, CY, fiscal, calendar, early, mid, late, a month name, or a quarter or half such as Q3 or H1, where the period ends (`in 2025.`, `mid-2025.`, `Q3 2025,`). Years listed after such a year as a range (`2023-2024`, `2023 to 2025`, `2023 vs 2024`) or a list that and or or closes (`2019, 2020, and 2021`), where the list ends. The one number after Chart or Charts, and the rest of a Charts list listed the same way where the list ends (`Charts 1 and 4.`). A list marker where a list starts, a heading's leading section number (`## 2. Sources`), and footnote marks. In `methodology.md`, a **Claim strength:** line the `claims` check accepts, which repeats its results' `state.md` Claim cell, design basis included, so its numbers trace to the record (`causal (experiment: randomized holdout of 2024 Q3, 50/50 split)`); only that source line, so a number on a line continuing its paragraph is read, and a line the `claims` check refuses keeps its numbers. Repair that line's `claims` row first: once the line matches `state.md`, its `numbers` rows clear with no `allowed_numbers` entry.
  - **Read.** So reported unless they trace or are allowed: `In June 77 orders`, `June 5 we met`, both numbers of `on June 5 77 orders`, `On June 5, 2026 we met` (2026), `in 2000 orders`, `Q3 2025 revenue` (2025), `(2025)`, `between 1950 and 2000 stores`, `Charts 1 and 4 show it` (4), `1950 orders`, `over 2025`, `2026 H1`, `Python 3.12`, `Week 23`, `top-10`, `Total,77`, `West/21.3%`, `100ms`, an ordinal such as `95th` (its number traces), and a number other than 1 that starts a line continuing a paragraph (`rose to` then `77. Orders`), which Markdown does not make a list; inside a list item or a quote too, unless the line is indented exactly as a list item on the line above (`- rose to` then `  77. Orders` reads 77; `1. a` then `2. b` is a list). An unindented number after a list item or an indented line starts a list.
  - **Allowed.** An `allowed` text covers a number wherever that text is written around it, matched on the text the number is read from: a space in it matches any whitespace or a line wrap, quote markers included, so a row's `text` copied exactly always covers its number. A bare `23` covers every 23 in both narratives, and the phrase `Week 23` only that one.
  - **Limit.** The check proves a number is among the recorded values, not that it is its claim's value or that both narratives give a claim the same number: with a large represented table most small numbers trace. Numbers written as words, such as three, or as a single symbol, such as ½, are not read, so write a claim's numbers in digits. Two skips can take a count: `chart` as a verb (`We chart 12 months`), and two counts from 1900 to 2099 written as a year range that ends a sentence (`rose from 1950 to 2040.`); write such counts with a separator (`1,950`) or reword. Recorded text is read line by line, so a scale on the line after its number (`$4.2` then `million`) records only 4.2, and the full written value is reported. The [draft review](review.md) confirms that every claim in `findings.md`, with its numbers, traces to the matching claim in `methodology.md`.
- `verify` and `compare_trees` rows: `path`, `kind` (`missing`, `extra`, `size`, `checksum`), `expected`, and `actual`. `compare_trees(local_dir, copy_dir)` compares every file, manifest included, with the local release as expected. Invalid inventories, missing or unreadable directories, and symlinks raise errors, which the commands report under `errors` or `problem`.
