# Diagnosing a helper's rows

`awb-init`'s `scripts/install_helpers.py` installs `src/packaging/draft.py` and restores it when missing. Call the project's copy, customized or not; open its source only to adapt or debug it.

- Every draft check reads `findings.md` and `methodology.md` through one reading in the helper (`_view`), so a form that hides text from a reader hides it from every check, and text a reader sees reaches every check. The reading covers this Markdown subset:
  - ATX `#` headings starting their line, indented at most three spaces. A heading's text is compared as it shows, with whitespace collapsed and code spans and autolinks unwrapped, so `` ### Revenue by `region` `` and `### Revenue by region` are one heading.
  - Paragraphs, block quotes, and bullet or numbered lists, nested or not, read in place. Tables read as text.
  - Fenced code starting at column 0, which is code.
  - Comments starting at column 0, ending on the line holding `-->`; text after `-->` on that line is read. A comment within a paragraph must close within that paragraph.
  - A **Claim strength:** line counts only opening a top-level paragraph at column 0; text on the lines below it may continue that paragraph.
  - A chart specification is a paragraph or list item that renders opening with `Chart N.`, as `**Chart N.**` does.
  - Inline markup is read as the text it renders. Emphasis and strikethrough markers and zero-width characters render as nothing, `<br>` as a space, and escapes and character references as the character they stand for, so `**leads** to` reads as leads to and `orders\_view` as orders_view. A link's or image's text joins the words around it and its target is dropped, though a methodology section's link targets still count as citations. A reference link `[text][label]` never resolves, since definitions are refused, so it shows as written and its label is read as text: `[carrier comparison][r-009]` cites r-009, and `[the view][orders_view]` is a `name` row. The claims check also reads it with the label dropped, as it would render resolved. A backslash hard break is a space, and a backslash before a backtick, `<`, or `&` makes it a literal character. CommonMark shows an unmatched marker as a character, so the claims check reads each marker both as nothing and as a word break: `x*drives` reads as drives. Code spans are code: the names scan reports them, at their opening line when one crosses a line break, and the claims check skips them.
  - Known limit: a square bracket outside a link renders as itself but is read as nothing, so a word glued to one joins the word inside it (`results[r-009]` reads as resultsr-009 and cites nothing). Leave a space before a bracket.
- `markdown` rows (`markdown_problems(draft)`): `file`, `line`, and `problem`, worded `unsupported Markdown: <what> at line N; rewrite as <how>`. One row is given for each form outside the subset that could hide text or move it between slides:
  - a heading, code fence, comment, or **Claim strength:** line inside a list item or block quote;
  - a fence or comment indented from the start of its line;
  - a **Claim strength:** line that is indented, inside a paragraph, or after a comment;
  - text underlined with `=` or `-` (a setext heading);
  - text indented four or more spaces, which renders as code;
  - an HTML block, or an inline HTML tag other than `<br>`, whose attributes can hide the text it wraps;
  - a link reference or footnote definition, which renders nothing where it stands;
  - a fence or comment never closed.
  A refused form is read as text, and its row fails the check, so nothing is guessed at.
- `findings` rows (`check_findings(path, *, names=(), roots=())`): `line`, `kind` (`code`, `path`, `file`, `identifier`, `sha`, or `name`), and `text`. Comments and Markdown link targets are skipped.
- A `name` row's `text` is a name from these sources: the investigation and package names; the view and table names created or read in `foundation/views/*.sql` and in the views the investigation's evidence cites, without CTE names or table functions; the settings keys of `settings.toml` and of the settings files and resolved settings that the investigation's evidence records, as top-level keys and the dotted path of every nested key (a nested key's bare name is usually a plain word, so it is left out); and the result IDs of `investigations/<investigation>/evidence/*.json` and the evidence links in its brief, state, and history. A name of letters only is never in the set, since it collides with ordinary words. `check-draft` passes those plain-word names as `roots` instead: a slash token with any recorded name as a segment, such as `orders/region`, is a `path` row, while a slash between two other plain words, such as yes/no, is prose.
- `charts` rows (`check_charts(findings_path, charts_dir)`): `chart` and `problem`, one per specification numbered out of order, specification without a file, file without a specification (worded to leave a blank line before it when the specification continues the paragraph or bullet above it, which renders it inside that block), non-chart file in `charts/`, or file without data rows.
- `headings` rows (`heading_problems(draft)`): `heading` and `problem` for a `###` finding heading that methodology has no section for, or that findings or methodology repeats.
- `claims` rows (`claim_problems(draft, represented, claims)`): a causal phrase above its slide's claim strength as `line`, `section`, `phrase`, `claim`, `results`, and `problem`; a represented result without a recognized Claim cell as `result` and `problem`; a finding without a methodology section, or whose section's **Claim strength:** lines are missing, repeated, unrecognized, at another strength, or, for a causal claim, naming a design other than the one `state.md` records for its cited results, as `section` and `problem`. Sections sharing a heading pool their citations and declarations. The phrase list is `_CAUSAL` in the helper; whole words only, so data-driven is prose.
- `verify` and `compare_trees` rows: `path`, `kind` (`missing`, `extra`, `size`, `checksum`), `expected`, and `actual`. `compare_trees(local_dir, copy_dir)` compares every file, manifest included, with the local release as expected. Invalid inventories, missing or unreadable directories, and symlinks raise errors, which the commands report under `errors` or `problem`.
