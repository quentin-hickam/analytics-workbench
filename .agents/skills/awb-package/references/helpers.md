# Diagnosing a helper's rows

`awb-init`'s `scripts/install_helpers.py` installs `src/packaging/draft.py` and restores it when missing. Call the project's copy, customized or not; open its source only to adapt or debug it. A helper or package format gates release, so change one only after the user says yes to the change, asked in plain words.

- Every draft check but `numbers` reads the narratives, `findings.md`, `methodology.md`, and `methodology-note.md` when the draft holds it, through one reading in the helper (`_view`), so a form that hides text from a reader hides it from every such check, and text a reader sees reaches every such check; `numbers` reads source lines as [number reading](numbers-and-evidence.md#numbers) says, outside the fenced code and comments this reading drops. The reading covers this Markdown subset:
  - ATX `#` headings starting their line, indented at most three spaces. A heading's text is compared as it shows, with whitespace collapsed and code spans and autolinks unwrapped, so `` ### Revenue by `region` `` and `### Revenue by region` are one heading.
  - Paragraphs, block quotes, and bullet or numbered lists, nested or not, read in place. Tables read as text.
  - Fenced code starting at column 0, which is code.
  - Comments starting at column 0, ending on the line holding `-->`; text after `-->` on that line is read. A comment within a paragraph must close within that paragraph. A `<!--` in a code span, fenced code, or a link's or image's target or title, or escaped as `\<!--`, opens no comment, so it hides nothing. Escapes are read first, as CommonMark reads them, so the backtick after an escaped backslash or backtick may open a code span: `` C:\\`<!--` `` holds one.
  - A **Claim strength:** line counts only opening a top-level paragraph at column 0; text on the lines below it may continue that paragraph.
  - A chart specification is a paragraph or list item that renders opening with `Chart N.`, as `**Chart N.**` does. Its fields are the list items directly under it that open with a field name (`Data:`, `Highlight:`, `Axis:`, `Interval:`, `Source:`, `Caveat:`, `Alt text:`) not yet given, each at the depth of the first; a blank line before the next one at that depth, or any other block, ends them, so a **Caveat:** bullet after a blank line is the slide's, and so is a field-named item back at a shallower depth. A field is one paragraph: an item nested under a field, a blank line before it or not, or a later paragraph inside one, is neither a field nor a bullet, and `charts` reports it; the fields after it still count.
  - The deck outline (`parse_outline(text)`, `read_outline(path)`) is derived from this reading and never written: the `#` heading and its first paragraph make the title slide; each `##` section but **Findings** and **Appendix** is a slide, and each `###` a finding slide, except that a `###` under **Appendix** headed with a template slide's name (**Answer**, **Implications**, **How we know**, **Limitations and open caveats**, **Open questions**, **What changed since the last version**, **Supporting datasets**) is that slide; slides under **Appendix** are marked `appendix` and keep their order, and `counts` gives the main sequence's slides, title included, and the appendix's, its divider not included; a slide's top-level list items are its bullets, deeper items nested under them; a paragraph opening **Headline:** or **Notes:** is its headline or notes. A paragraph in a block quote is a paragraph of its own, unless the quote sits in a list item, where it continues that item. A later paragraph in a list item continues that item only when no deeper item comes between them; after a deeper item it is a paragraph of its own, so it is reported rather than joined to the deeper item or a chart field: by `charts` when it sits at a chart field's depth or deeper, as text inside that field, and otherwise by `outline`.
  - Inline markup is read as the text it renders. Emphasis and strikethrough markers and zero-width characters render as nothing, `<br>` as a space, and escapes and character references as the character they stand for, so `**leads** to` reads as leads to and `orders\_view` as orders_view. A link's or image's text joins the words around it and its target is dropped, though a methodology section's link targets still count as citations; only the `questions` check reads an image as the picture it shows, without its text. A reference link `[text][label]` never resolves, since definitions are refused, so it shows as written and its label is read as text: `[carrier comparison][r-009]` cites r-009, and `[the view][orders_view]` is a `name` row. The claims check also reads it with the label dropped, as it would render resolved. A backslash hard break is a space, and a backslash before a backtick, `<`, or `&` makes it a literal character. CommonMark shows an unmatched marker as a character, so the claims check reads each marker both as nothing and as a word break: `x*drives` reads as drives. Code spans are code: the names scan reports them, at their opening line when one crosses a line break, and the claims check skips them.
  - Known limit: a square bracket outside a link renders as itself but is read as nothing, so a word glued to one joins the word inside it (`results[r-009]` reads as resultsr-009 and cites nothing). Leave a space before a bracket. For the same reason, and because an unmatched `*` reads as nothing even when escaped, a **Data:** line cannot name a chart column whose header holds `[`, `]`, or `*`; give the column a header without them.
- `methodology-note.md`, when the draft holds it, is read by the `findings`, `markdown`, `claims`, and `numbers` checks below and by `review-rules check` as the other narratives are; its rows carry `file`. Only an absent note is skipped: one that cannot be read is an error.
- `markdown` rows (`markdown_problems(draft)`): `file`, `line`, and `problem`, worded `unsupported Markdown: <what> at line N; rewrite as <how>`. One row is given for each form outside the subset that could hide text or move it between slides:
  - a heading, code fence, comment, or **Claim strength:** line inside a list item or block quote;
  - a fence or comment indented from the start of its line;
  - a **Claim strength:** line that is indented, inside a paragraph, or after a comment;
  - text underlined with `=` or `-` (a setext heading);
  - text indented four or more spaces, which renders as code;
  - an HTML block, or an inline HTML tag other than `<br>`, whose attributes can hide the text it wraps;
  - a link reference or footnote definition, which renders nothing where it stands;
  - a fence or comment never closed.
  A refused form is read as text, except a fence or comment starting at column 0, outside lists and quotes, that is never closed, which hides the rest of the file from every check, `numbers` included, as it would render. Either way its row fails the check, so nothing is guessed at.
- `findings` rows (`check_findings(path, *, names=(), roots=())`): `line`, `kind` (`code`, `path`, `file`, `identifier`, `sha`, or `name`), and `text`. Comments and Markdown link targets are skipped.
- A `name` row's `text` is a name from these sources: the investigation and package names; the view and table names created or read in `foundation/views/*.sql` and in the views the investigation's evidence cites, without CTE names or table functions; the settings keys of `settings.toml` and of the settings files and resolved settings that the investigation's evidence records, as top-level keys and the dotted path of every nested key (a nested key's bare name is usually a plain word, so it is left out); and the result IDs of `investigations/<investigation>/evidence/*.json` and the evidence links in its brief, state, and history. A name of letters only is never in the set, since it collides with ordinary words. `check-draft` passes those plain-word names as `roots` instead: a slash token with any recorded name as a segment, such as `orders/region`, is a `path` row, while a slash between two other plain words, such as yes/no, is prose.
- `outline` rows (`outline_problems(findings_path)`): `slide` (a slide's heading, `title`, or where stray text sits), `line`, `problem`, and `severity`, one per break of the slide rules: no `#` title or subtitle line; anything else on the title slide; text before the title, under a second `#` heading, or under **Findings** before its first finding; a `###` finding outside `## Findings` and `## Appendix`; a **Headline:** line on a finding slide, or none or several on another; an empty headline or one over 15 words (counting whitespace-separated words that hold a letter or digit), the one `warning` row, which also carries the `headline` text and, in `check-draft`, `accepted`: true once the manifest's `accepted_long_headlines` lists that exact text with a reason, which passes it; a bullet opening with a chart field name other than `Caveat:` right after that chart's fields ended, naming the chart; more than five bullets except on **Open questions**, naming the chart when some of them are such bullets; more than one chart; a paragraph that is no headline, chart, or notes; and no **Notes:** paragraph, several, or text after it. The title slide needs no notes, and holds at most one **Notes:** paragraph. The required slides give a row when missing, repeated, or out of order: no **Answer**, or one that is not the first slide after the title; no finding slide in the main sequence; no **How we know** or **Limitations and open caveats** in the main sequence or under **Appendix**, or one in the main sequence before a finding slide, or **Limitations and open caveats** before **How we know** when both stand in the main sequence or both under **Appendix**. **Appendix** gives a row for text before its first slide, a slide after it outside it (a `##` slide, or a `###` finding under a later **Findings**), a second `## Appendix`, a slide that stays in the main sequence (**Answer**, **Implications**, **Open questions**, **What changed since the last version**) placed under it, and an appendix holding no slide. A missing slide's `line` is null.
- `helper_drift` rows (`helper_drift(root)`): `file`, `status` (`changed`, `missing`, or `unreadable`), `sha256` (now, `null` when missing), `recorded` (the receipt's), and, in `check-draft`, `confirmed`, for each file under `src/` or `package-format/` that differs from the SHA-256 `.awb-receipt.json` records. A project without a receipt, or a file it does not record, gives none; an unreadable receipt is a row of its own. `confirmed` is true when the manifest's `helper_drift_confirmed` lists that `file` at that `sha256` with a reason. The rows never fail `check-draft`; `release` refuses while one is unconfirmed. The check runs in the project's copy of this helper, so an edit that removes it also hides the change.
- `storyline` rows report the finding slides to move: those outside the longest run of slides already in ledger order, each with `slug`, `position`, `expected_position`, and the `question` that ranks it, so one moved slide is one row. The main sequence's finding slides and the appendix's are ranked separately, the appendix's positions numbering on from the main sequence's; `ledger_order` lists that order. When the manifest's `presentation_order` is a list, it ranks every finding slide instead, and rows report, by `slide` or `slug` and `problem`, a malformed field (not `none` or a list of non-blank text), a slug listed twice, a slug no finding slide has, a finding slide it does not list, and each slide out of its order, with `position` and `expected_position`. A slide's primary result is the first represented result its matching methodology section cites (`finding_primaries(draft, represented)`): a code span holding only the ID, or an evidence path, `evidence/<ID>.json`, anywhere in the text or a link target; within one line its text is read before its link targets. That result's recorded settings `answers` supply its question IDs; the results cited after it supply none. Slugs (`slide_slugs(slides, recorded)`) come from the manifest's `slide_slugs`: a slide keeps the slug recorded with its exact heading, else the one recorded with its primary result when no other unmatched slide shares that result, else it takes the first six words of its heading, ASCII letters and digits joined by hyphens, numbered `-2` past a slug another slide holds; a slide citing no result keeps its slug only under its exact heading, and `export` and `check-draft` keep the recorded slugs while `headings` lists a row. The [contract's Ledger storyline](package-contract.md#ledger-storyline) gives the ordering rule. `unlinked_findings` names slides answering no ledger question; it is informational, and without a `presentation_order` those slides go last. Missing evidence supplies no declared linkage and is reported here; existing evidence must name readable TOML with that result's settings table, whose answers must be a list of existing data question IDs. Malformed declarations fail, including when the ledger is empty.
- `open_questions` rows report a missing or unnecessary **Open questions** slide, a slide in the wrong position, or required question bullets missing, repeated, or replaced by other text. The input is the outline reader's rendered top-level bullet text, compared exactly to rendered ledger question text; inline formatting uses the subset above. Nested bullets and charts are refused on this slide. Paraphrases, question IDs, and owner commentary are not alternate matching forms. This check does not judge whether ledger wording suits the audience; the draft review does. The [contract](package-contract.md#ledger-storyline) defines which questions belong and why this slide has no five-bullet cap.
- `charts` rows (`check_charts(findings_path, draft)`): `chart` and `problem`, one per specification numbered out of order, specification without a file, file without a specification (worded to leave a blank line before it when the specification continues the paragraph or bullet above it, which renders it inside that block), other file named `chart-*`, or file without data rows; then, per specification, a form outside the seven in `deck-rules.md`, no **Data:** line, an entry that is not `role: column header`, a role its form does not take, a role named twice that the form takes once, a role the form needs and the line lacks, a series with more than one value, a named column the file's header lacks (the header compared as the line renders, as `deck-rules.md` states for builders, so `CO₂` matches `CO₂`), a column of the file's header that the line names by no role (`chart_data(chart)` reads the **Data:** line), and an item nested under a field or a later paragraph inside one, by its line. A `lower` or `upper` role on a form that plots values without intervals says that only a Bar with intervals draws interval columns; an unnamed column there says so in case it holds interval bounds.
  - **Chart files.** `charts` also holds `chart_file_problems(root, investigation, draft, record)`'s rows: a chart file the manifest's `charts` does not record (`none` and an absent field record none), an entry whose file is missing, an entry that does not record the shaping `export` writes (an earlier export's `path` and `result_id` alone), an entry whose `headers`, value labels, `percent` columns, or `scale` divisors differ from what `foundation/display.toml` now gives for its result and selected rows (its `round` places may come from `--round`, so they are taken as recorded), and a file that differs from its result's saved table under that entry's selection, value labels, percent columns, and rounding, naming its header, a row, or the row count. A differing file is refused even when every value in it is recorded: rows are selected with `--chart`, never by editing the file. The `numbers` check is unchanged, since every plotted value is still a recorded value, or one divided by its recorded `scale` divisor, which it also traces.
- `draft_markers` rows (`draft_markers(findings_path)`): `where` (`title`, `subtitle`, `heading`, `headline`, or `title notes`), `line`, `marker`, and `text`. A marker is the word draft or the phrase working copy or not a numbered release, in any case and as whole words, so drafted, redraft, and working copies are not. Only the places a deck names its own status are read, as they render: the `#` title, its subtitle, each slide's heading and **Headline:** text, and the title slide's **Notes:**. Bullets, charts, and other slides' notes are not. The rows are informational and never fail the check; `awb-release` shows them before releasing.
- `note_length` rows (`note_length_problems(root, investigation, draft)`): when the draft holds `methodology-note.md` and the investigation's `brief.md` has a line `Methods note length: about <n> words` (a bulleted or numbered list marker before it and a closing period allowed), one row with `file`, `words`, `recorded`, and `problem` when the note, counted as it renders (headings, text, and list items, not comments or fenced code, a fence's language label included), runs more than 10% over `n`. A brief line that starts like that one in any other form, after a list marker, `>`, `|`, or `**`, or as `Methodology note length`, or a second line with another length, is a row naming the brief's `file` and `line`, so a length written another way is reported rather than read as none. Informational, like `slides`: it never fails the check.
- `review` row: `status` and `changed` from `review-receipt show` (`review_receipt(root, investigation, package)`), informational in `check-draft` and the gate `release` refuses on unless `current`. The record is `deliveries/<investigation>/<package>/review/`: `receipt.json` and `snapshot/`, a copy of what the review read, the narratives, the investigation's `brief.md`, `foundation/glossary.md`, `foundation/sources.md`, and `foundation/quality.md` whole, `foundation/review-rules.md` without the sections of rules kept for another package (the whole file when it has problems, none when no rule holds for the package), the manifest's `revalidation_flags` reduced to each entry's finding, reason, `represented_in`, and whether its disposition is `omit`, and each evidence file the manifest's `results` name and each scan `methodology.md` names by its `foundation/scans/<name>.json` path and each saved query by its project-root `.sql` path (stored under `snapshot/evidence/`; a scan cited another way, such as by its marker alone, is not read, so its rescan leaves the review current), and the SHA-256 of each project file a Sources row's `reference:` links to; `changed` names those inputs, the brief as `brief.md` and an evidence file, scan or saved query by its path, and `diff` runs from the copy, the rule file's line numbers counting only the rules that hold for the package, cut so `show`'s printed line fits one MCP read, `AWB_MCP_MAX_CHARS` (`diff_cut`). `start`, run right before the reviewer is launched, writes `review/started.json`, the kind and a digest of each of those inputs, and refuses `--kind scoped` with no record; `record` without `--accept` needs a start of its kind, refuses when an input differs from what the start saw, and consumes it. A report that does not pass is also refused when it is the recorded one, accepted or not, and `show` reports `stale`, or when it was refused for a change after an earlier start, whose digest `started.json` keeps and each `start` carries until a record consumes it; that note is all a refusal writes. A new reviewer returning that report, formatting aside, is refused too. A report that passes, such as a clean one, is not checked, since the Brief fixes its words. `record` cannot tell that a reviewer was launched after `start`, so that order is review.md's **Launch**, nor that a reviewer, not a hand, wrote the report. `--accept` amends the recorded report and refuses once what it read has changed, or for another report. `record` reads the report's last non-blank line, backticks and a closing period allowed, and counts rows under any markers, in bold or backticks, singular or plural words; it refuses a last line in no step 4 form, a `--kind` that line contradicts, and a report listing more `R-... violation` or `narrative` rows of a kind than that line counts.
- `START-HERE.md` (`start_here(draft, investigation, package)`): plain text in three parts, written by `check-draft` without `--verify-only` before the inventory. **Send these to your audience** lists the deck once built, `methodology-note.md` when the draft holds it, and each `dataset-*.csv`; **To build the deck** lists `findings.md`, each chart file, `methodology.md` and `deck-rules.md`, each marked for the builder only, and `m365-assembly.md` to attach, and the one-line prompt it gives; **Internal: keep these; do not send them to the audience** names `manifest.json` and the files part 2 attaches, so each file is listed once. It follows the files the draft holds, so the next `check-draft` rewrites it after any change; the report's `start_here` names it.
- `headings` rows (`heading_problems(draft)`): `heading` and `problem` for a `###` finding heading that methodology has no section for, or that findings or methodology repeats.
- `questions` rows (`question_problems(draft, record)`): `result_id` and `problem`, with `question` when the manifest records one, for a `results` entry without a question, or whose question `methodology.md` does not repeat verbatim as it renders. Each paragraph or heading is read as it shows, code spans unwrapped and whitespace collapsed, and the question matches as written or rendered the same way, so a question wrapped across lines or written with emphasis or a link still matches. It must fall within one paragraph or heading. A code span counts, since it shows its text: a question shown exactly in one matches even when it holds a markup character such as `[`, `~`, `*`, `_`, or `\`. A question only in a comment, in fenced code, or in an image's text does not count: an image shows a picture, and its text only when it fails to load or to a screen reader. So an image's text is left out, though the other checks read it, and a question cannot run across an image.
- `claims` rows (`claim_problems(draft, represented, claims)`): a causal phrase above its slide's claim strength as `line`, `section`, `phrase`, `claim`, `results`, and `problem`; a represented result without a recognized Claim cell as `result` and `problem`; a finding without a methodology section, or whose section's **Claim strength:** lines are missing, repeated, unrecognized, at another strength, or, for a causal claim, naming a design other than the one `state.md` records for its cited results, as `section` and `problem`. Sections sharing a heading pool their citations and declarations. A template slide under **Appendix** keeps its rule there, and an appendix finding slide is held like any other. `methodology-note.md` is read at the strongest represented claim, each row's `section` its heading, except its `## Limitations` section and the `###` sections under it, which are not read, as the deck's **Limitations and open caveats** slide is not. The phrase list is `_CAUSAL` in the helper; whole words only, so data-driven is prose.
  - **Negated clauses.** A phrase in a negated clause is skipped, under a closed grammar: a negator (not, never, cannot, neither, nor, a word ending in n't, no before evidence, sign, indication, proof, support, or test, or without before an -ing word) at most four words before it in its clause, or directly before it for because of, due to, as a result of, or attributable to, so `not due to weather` passes and `did not fall due to weather` is a row; or, after a noun phrase (effect of or on, impact, drivers of, causes), is, are, was, were, remains, or stays unknown, unclear, untested, or not known, established, or tested, at most four words after it. A clause ends at a paragraph or item break, at `.`, `;`, `:`, `,`, `!`, `?`, a parenthesis or bracket, or a dash, and at but, and, while, whereas, although, though, or however. Not only, not just, not merely, and not simply negate nothing, and a who, whom, whose, which, that, or where before the negator in its clause, or between the noun phrase and its predicate, puts the negation in another clause, so `does not test what caused them` and `the effect on repeat rates is unknown` pass while `stores that did not discount drove the rise` and `not only did discounts drive sales` are rows. Known limit: a negator the grammar takes that negates something else within four words, such as `customers not renewing drove the drop`, skips the phrase; the [draft review](review.md) reads the wording.
- For `numbers` rows, tracing, and skipped contexts, see [number reading](numbers-and-evidence.md#numbers).
- `export` shapes each file from `foundation/display.toml` (`display_names(root)`), which holds only `[columns]` (column = display name), `[values.<column>]` (coded value = label), `[round]` (column = decimal places, a whole number from 0 to 20), `[percent]` with one key, `columns = [...]`, `[scale]` (column = `{ divide = <positive number> }`, optionally `files = false` for prose only, as `change_mt = { divide = 1000, files = false }`), `[confirmed]` with one key, `columns = [...]`, and `[results."<result>"]` tables holding `columns`, `values`, and `percent` tables. Any other key, or a table of another shape, is an `errors` row and nothing is written. A result's own `columns` name wins over the global one for its files, its `values` table for a column replaces the global one whole, so a code it lacks stays as written, and its `percent` list replaces the global `[percent]` list whole, so a column that already holds percents in that result takes `columns = []` there and is not scaled again. A cell takes its value label first, a code matching the saved text exactly, so a boolean pandas saved takes `"True"`, never `true`; otherwise a number cell (an optional sign, digits with an optional decimal point, and an optional exponent, finite as a float) in a `[scale]` column with `files` omitted or true is divided by its divisor, one in a `[percent]` column is multiplied by 100 exactly from its saved text, and one in a column with places is rounded half up to them, in that order. Other text, a thousands separator or NaN included, is written as saved. The `charts` and `dataset_selection` entries record file divisors as `scale`, prose-only divisors as `prose_scale`.
  - **Gaps.** A column without a non-blank name is an `errors` row, listed with `display_stub`. A column is unrounded when a number cell the file holds, its value label aside, has more than four decimal places in its saved text, the text the file shows unless rounded, once trailing zeros are dropped, any exponent applied, its file divisor applied, and a `[percent]` column's 100-fold scaling applied, so a `[percent]` column's saved fraction may carry six: `366.89000039169395`, `1e-05`, and `21.35000000000000142` are unrounded, `21.3500` (which is `21.35`), `1.2345`, and `1.5e3` are not. Digits beyond a float's precision count, since the file shows them. An unrounded column that `[round]` and `--round` do not cover is an `errors` row naming an example cell, listed with `round_stub`, one `"<column>" = ""` line per column to paste under `[round]` once each `""` is replaced with the places the brief's precision gives, unquoted, such as `"share" = 1`; a `[round]` entry that is not a whole number from 0 to 20, a pasted stub left blank included, is its own row and is fixed in place. Every gap is listed together, and nothing is written.
  - **Row selection.** `--chart` takes a closed grammar, `RESULT[:COLUMNS][@first=<n>|@where=<column>=<value>[,<value>]]` (`parse_chart(text)`). The first `@` opens the selection, so a column whose name holds `@` or `,` cannot be named in `COLUMNS`; the `@where` column may hold either. Before it, `RESULT` is a simple name, and the first `:` opens the columns, comma-separated, stripped, and none empty; a `:` after the `@` belongs to the selection. `@first=<n>`, `n` a whole number from 1 to 999999999 without leading zeros, takes the saved table's first `n` rows, which the result's stable total order fixes. `@where=<column>=<value>[,<value>]` takes, in table order, the rows whose column holds one of the values exactly as the saved table writes it, before value labels; the column ends at the first `=` and is stripped, and no value may be empty or hold `,`. Text outside the grammar is refused with exit status 2 and an `errors` row naming the part that does not fit; a selection naming a column the table lacks, a value no row holds, or more rows than the table has is an `errors` row; nothing is written. A `--dataset` takes no selection. The manifest's `charts` entry records `selection` as `all`, `{"first": n}`, or `{"where": {"column", "values"}}`, with the `columns`, `headers`, value labels used (`values`), `percent` columns, and `round` places, which `check-draft` reapplies.
  - **methodology_lines.** One line per selection and header, each prefixed with the file's label (`chart-1`, or the dataset name): `rows <- the first 10 rows of <result>` or `rows <- the rows of <result> whose <column> is <value> or <value>` when a chart selects rows, then `<header> <- <result>.<column>`, followed by `, times 100` for a `[percent]` column and `, rounded to <n> decimal places` (or `to whole numbers`) for a column with places, each after `, divided by <n>` for a file-scaled column; prose-only divisors get a separate line, so `methodology.md` states the manifest shaping.
  - **Warnings.** Each is a warning: the files are written. `label_warnings`: each column whose global `[columns]` name labels files from results with different recorded questions, none of them naming it under its own `[results."<result>".columns]` and `[confirmed]` not listing it, as `column`, `name`, `results`, and `warning` (`label_collisions(display, files, questions)`); list a column under `[confirmed]` once its name is confirmed to fit every result. `value_warnings`: each code of a value table that no cell of the saved tables it labels in this export holds, when a cell differs from it only in case, which the row names, or when no code of that table matches any cell, as `table`, `code`, and `warning` (`value_warnings(codes)`); a shared table listing codes these results leave out gives no row. `precision_warnings`: each `[percent]` column shown to fewer than two places whose selected fractions include one saved to exactly four places, a sign the query rounded it so the display rounds it again, as `result_id`, `column`, `example`, and `warning`; save the result at full precision and round only under `[round]`.
- `verify` and `compare_trees` rows: `path`, `kind` (`missing`, `extra`, `size`, `checksum`), `expected`, and `actual`. The inventory, and so both, leave out a top-level `.preview/` folder, the headline preview, which `release` does not copy. `compare_trees(local_dir, copy_dir)` compares every file, manifest included, with the local release as expected. Invalid inventories, missing or unreadable directories, and symlinks raise errors, which the commands report under `errors` or `problem`.
