# Landing helper

Call the project copy at `src/preparation/landing.py`. The `land`, `retain`, `publish`, and `sql` commands cover supplied files and select-based conversions; `python3 src/awb.py <command> --help` gives each one's arguments and output. This reference covers the two library calls for what the commands cannot do, landing archives, spreadsheets and multi-part extracts, what the read-only commands read, and the source reference grammar `awb-status` reads.

## Fetch a source with `land()`

For an API or other fetched source, call `land()` from a script with a `fetch` callable, then run `python3 src/awb.py retain` to retain the acquisition and write its Acquisitions row.

`land(root, source, acquisition_id, fetch, *, request, records=None, upstream=None, notes=None) -> Path` calls `fetch(partial_directory)`. The callback writes every original file and raises on incomplete acquisition; its return value is ignored. `request` and `notes` must be JSON serializable. `records` maps relative filenames to integer counts; omitted counts become null. `upstream` maps relative filenames to the validators the server returned, any of `url`, `etag` (the ETag header as sent), `last_modified` (the Last-Modified header as sent), and `version_id` (an object-store version), each a string; omitted fields and files become null. `land()` reads both after `fetch` returns, so `fetch` can fill them as it writes. `url` must carry no credentials, because provenance `files` are copied into committed result evidence: `land()` refuses a `url` with a user name or password, with or without `//` before the host, or with a parameter whose name, lowercased without punctuation, ends in `key`, `token`, `secret`, `sig`, `signature`, `password`, `passwd`, `credential`, `credentials`, `session`, `sessionid`, or `sessid`, or is `pass`, `pwd`, `auth`, `authorization`, `sid`, or `jwt`. A parameter is a `name=value` in the query, the fragment, or a path segment after its first `;`, each separated by `&` or `;`; its name is percent-decoded before the check. Record the URL without them; a resource that needs them then probes as unknown. An `http` or `https` `url` must also be one a request can be sent to as recorded: `land()` refuses one without a host, with a port that is not a number from 0 to 65535, or with a space or control character. The check goes by name alone, so a parameter that selects content, such as `sortkey`, is refused too: record no `url` for that file, since dropping the parameter would point the probe at a different resource. The refusal comes after `fetch`, so the fetched files stay in the `.partial` directory, and a `fetch` that copies them from there can land them under a new acquisition ID. `provenance.json` is reserved. After `fetch` returns, `land()` checks the files and `records`, hashes the files, writes provenance, and renames the directory from `.partial`. If `fetch` or any of these steps fails, the directory keeps its `.partial` name and every file `fetch` wrote, including a `provenance.json` it wrote by mistake; `land()` removes only the provenance it wrote itself.

Record `upstream` whenever the fetch has these values: with an HTTP URL and an ETag or Last-Modified, `awb-status` can report on request whether the upstream file has changed since. A server that sends neither leaves the source uncheckable: `retain` prints `upstream_check` for the acquisition, so tell the user once, at landing, that upstream changes to it cannot be detected. A changed upstream is landed again under a new acquisition ID; `land()` never replaces an acquisition.

The fetch script reads credentials from environment variables, with local values in the gitignored `.env`; the project's `workbench-guides/data.md` (**Assess and acquire**) holds the full rule. Where `request` or `notes` refers to a credential, it names the variable, as `$NAME`, never its value; `land()` records both as given, without checking them.

## Convert with `publish()`

For a conversion a select cannot express, call `publish()` with a `convert` callable.

`publish(root, dataset, publication_id, convert, *, acquisitions, validate=None, notes=None) -> Path` calls `convert(partial_directory)`, runs the dataset's checks declared in `foundation/datasets.toml` over the Parquet files it wrote, then calls `validate(partial_directory)`. A malformed declaration of any dataset, or declared checks without the `duckdb` package, refuses before `convert` runs. A failing declared check raises `ChecksFailed`, whose `checks` lists every declared check. Use `validate` for checks a declaration cannot express: raise on failure or return the Python boolean `False`; every other return value permits publication, and a returned string becomes the detail of its `validate` check. `acquisitions` lists completed acquisition directories, absolute or project-relative. Conversion reads them without modification. `publication.json` is reserved; the helper records inputs, hashes, Git HEAD (or `uncommitted`), and the checks with their outcomes, then renames the output directory. Record the publication in `foundation/catalog.md` as the `publish` command's `catalog_row` would.

## Archives, spreadsheets and multi-part extracts

Land an archive, such as a `.zip`, as received. DuckDB reads no member inside an archive, so extract the members a conversion needs into a folder outside the project, then land the archive and that folder in one call, so the acquisition's provenance hashes both and retention copies both:

```sh
python3 src/awb.py land <source> <acquisition-id> <archive>.zip <extracted-folder> --notes "<archive>.zip is the original as received; <extracted-folder>/ holds the members extracted from it"
```

The archive is the retained original and the extracted members are the form conversions read; the `--notes` text records which is which in the Acquisitions row. A spreadsheet landed on its own is its own original.

Publish a workbook (`.xlsx`) through DuckDB's spreadsheet reader, `read_xlsx`, which comes from the `excel` extension: install it once as the next section says. Name the sheet, and read every cell as text with `all_varchar = true`, so no column's type is guessed from its first rows; cast each column in the SELECT:

```sql
SELECT ... FROM read_xlsx('data/raw/<source>/<acquisition-id>/<extracted-folder>/<book>.xlsx', sheet = '<sheet>', all_varchar = true)
```

Under `all_varchar`, a date cell can arrive as its Excel serial day number, such as `45292` for 2024-01-01, and a date-time cell with the time of day as its fraction, such as `45292.75` for 18:00 that day. Convert a date explicitly, `DATE '1899-12-30' + CAST(FLOOR(CAST(<column> AS DOUBLE)) AS INTEGER)` for a workbook in Excel's default 1900 date system (right from March 1900 on) or the same from `DATE '1904-01-01'` for one in the 1904 system. `FLOOR` drops the time: a cast to `INTEGER` alone rounds, which moves every cell from noon on to the next day. To keep the time, convert to a timestamp, `TIMESTAMP '1899-12-30' + to_milliseconds(round(CAST(<column> AS DOUBLE) * 86400000))`, or the same from `TIMESTAMP '1904-01-01'`. Check a few converted values against the workbook before publishing, including one with an afternoon time.

A conversion that combines several sheets, files or partitions adds lineage columns saying where each row came from, such as `sheet` and `sheet_row`, and declares them as `lineage = ["sheet", "sheet_row"]` under `[datasets.<dataset>]` in `foundation/datasets.toml`, so `awb-clean`'s duplicate scan compares rows without them. Sheets or extracts covering overlapping periods can hold the same rows twice. Before publishing, count each pair's shared rows on the non-lineage columns, such as `SELECT count(*) FROM (SELECT * EXCLUDE (sheet, sheet_row) FROM (<select>) WHERE sheet = 'A' INTERSECT ALL SELECT * EXCLUDE (sheet, sheet_row) FROM (<select>) WHERE sheet = 'B')`, and report any overlap; `awb-clean` removes and records an exact copy across parts.

## Read landed files without writing

`sql --read-only`, `profile --read-only`, and the MCP `read` tool run SELECT statements whose table functions read files or the catalog. The file readers include `read_csv`, `read_parquet`, `read_json`, `read_text`, `read_blob`, and `read_xlsx`, so a read-only query can read a landed Excel file, for example to check it before writing its conversion. `read_xlsx` comes from DuckDB's `excel` extension. The read-only session installs no extension but loads one already installed. Install it once without `--read-only`: `python3 src/awb.py sql "INSTALL excel; SELECT 1"`, or the `data` tool's `sql` over MCP. `read_xlsx` writes nothing: its arguments name a file, a sheet, and a range, and only `COPY` writes an `.xlsx`, which read-only SQL refuses. Reading an `.xlsx` without the extension, through `read_xlsx` or a plain `FROM 'book.xlsx'`, fails on one line saying how to install it.

Read-only SQL also refuses SQL built from a string, because the plan it checks need not be the plan that runs: `query()`, `query_table()`, and the macros calling them, such as the `histogram` and `histogram_values` table macros. The `histogram()` aggregate runs. A view file's CREATE whose body does not parse alone, such as a macro with two bodies or a `CREATE TABLE ... WITH NO DATA`, is checked by token, so `histogram()` is refused there too, and the refusal says so. Once a view file's CREATE MACRO runs, the session reads the macro's body back from DuckDB's catalog and refuses the view file if that body calls SQL built from a string.

## Both calls

Both refuse existing final or partial destinations. A failure leaves an unpublished partial directory, which a retry under the same ID refuses. A publication's partial holds only output: remove it before publishing again, as the `publish` refusal's `next_step` says. An acquisition's partial holds the fetched files: land them under a new acquisition ID or remove it. Source, dataset, and run identifiers are single directory names, excluding `.`, `..`, and names ending in `.partial`.

## Source references

`awb-status` reads a reference in a `foundation/sources.md` Notes cell by syntax alone, ignoring letter case, and opens no link, location or checksum. A clause counts when it is in plain text, not inside code, HTML, emphasis, strikethrough, a link or brackets, opens the cell or follows `;`, `,`, `.` or `<br>`, and begins `reference:` followed directly by one of the forms:

- A link, `[text](destination)`. The text is not empty and has no `[`, `]`, `\`, `<` or backtick. The destination is either in angle brackets with no `<`, `>` or `\` inside, which allows spaces, such as `[codebook](<references/hr/data dictionary.pdf>)`, or bare, with no spaces, `<` or `\`, and with its parentheses balanced.
- A retained location in single backticks, a comma, and `sha256` with the full 64-digit checksum and no letter, digit, `_`, `\` or `&` directly after it. `SHA-256` and `sha256:` are also read.
- An access note, `read at <URL> on <YYYY-MM-DD>, not kept: <reason>`, with an `http` or `https` URL, bare or in angle brackets. Status lists a source whose only reference is an access note under `documentation_access_notes`, a known limitation, not as lacking a reference.

Any other spelling counts as no reference, including Markdown that renders as a link, such as a link with a title or with brackets in its text. Reading also stops at a link with a title or with a destination neither form allows, at any raw HTML other than `<br>`, at an autolink containing a backtick, bracket or `<`, and at a `*`, `_` or `~` that opens emphasis or strikethrough when a backtick, bracket, `<` or an opening `*`, `_` or `~` of another kind comes before the cell's last `*`, `_` or `~` of that kind that could close it, so put reference clauses before them. Status names the reason with each source it lists. To fix one, rewrite it in a form: drop brackets and backslashes from the link text, write paths with `/`, and put a path with spaces or unbalanced parentheses in angle brackets.
