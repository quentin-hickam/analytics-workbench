# Result evidence helper

Call the project copy at `src/provenance.py`; its module docstring holds the full `awb-evidence/3` schema.

## The findings row

A result that raises prints `{"result_id", "error"}` with the traceback on stderr, the other results still run, and `run.py` exits 1. Before it unlinks the evidence, `run.py` calls `prior_result()`, which captures the `evidence_commit()` citation and, as the baseline, the saved table's sha256 with the evidence's checks and scoped settings. After `record_evidence()`, `record_finding()` writes the result's one row and `run.py` prints `state`: `added` (a `provisional` placeholder row), `kept` (baseline unchanged, nothing written), `refreshed`, or `flag cleared`. A refreshed row becomes `provisional` unless superseded and gets a history entry when it was supported; a flagged row returns to `superseded` or `provisional`, keeping its notes and dropping its flag reason, which the history entry records; a row flagged before `findings.json` existed holds its notes in that reason, so they go with it. Each entry's `notes_checks` records the checks caveat its notes were written against, and `state finding` counts the notes as explaining failed or not-assessed checks only while it equals the current one. The caveat's `failed checks:` and `not assessed:` segments are reserved for the writer; other segments are notes from `awb.py state finding --caveat`. `findings.json` (`awb-findings/1`) owns all four cells; the first findings write, or `prior_result()` before a rerun, migrates a legacy table in memory: the Evidence cell becomes its one link and status case, caveat order, and whitespace are normalized and reported, and a row without exactly one evidence link or with an unknown status is refused before anything changes. Writers refuse table drift, and `prior_result()` checks before a rerun removes evidence. `python3 src/awb.py state render --investigation <name>` restores the JSON table and prints discarded rows; re-apply intended edits with `state finding`, or flags with `state flag` (a JSON list of `result` and `reason` on stdin; `--check` validates without writing). Only table rows are rendered, and a row cut off below the table still counts as drift; `state issues` and `state next` never touch the table. All temporary files are written first, then findings, state, and history are replaced in order with signals deferred. New evidence is removed only if findings.json was not replaced. A failed state replacement names `state render`; a failed history replacement names its missing prior rows. A kill or power loss between replacements can still leave the table behind findings.json, which `state render` restores, or lose the history entry, risks accepted over a recovery mechanism. `finding_row()` returns the row without writing it.

The saved table under `results/` holds the computed values packaging later serializes. `results/` is output, not producing code. `run.py` deletes a result's evidence before rewriting its table, so a run that fails partway leaves no evidence rather than evidence for another table.

## Adapt what a result records

`run.py` records each result through `record_evidence()`. Set `views = [...]` in a result's settings when its producer reads views its queries do not name (detection errs toward recording a view). Producing code is `run.py`, the result's own `queries`, the investigation's other code, and `src/` except `awb.py`, `provenance.py`, and `packaging/`, which only dispatch, record, or package; another result's queries never make it stale. Pass `code_paths=[...]` in `run.py`'s `record_evidence` call to add producing code outside those, such as exploration SQL a producer reads. Unknown provenance is recorded as `{"unknown": reason}`.

Settings are recorded per result: `record_evidence()` refuses a settings file without the result's `[results.<id>]` table, and the evidence keeps only `[parameters]` and that table, compared by content alone. Adding or editing another result's table, or another top-level table such as `[eda]`, leaves the result current, while a change to `[parameters]` or its own table fails the `settings` comparison. Keep anything a result reads in `[parameters]` or its own table.

## Evidence comparison

`awb-package`'s `export` command and `python3 src/awb.py stale`, run `compare_evidence(root, evidence_path)`: five comparisons in order (`committed-code`, `uncommitted-code`, `views`, `inputs`, `settings`), each `{name, paths, outcome, detail}`. It compares state; it does not revalidate. It reads only `awb-evidence/3` files whose settings name their result; any other evidence fails all five comparisons, so rerun its result.
